> 이 문서는 **GridBrawl**의 게임 룰·설계 의도·현재 구현 상태를 한곳에 모은 단일 진실 공급원(single source of truth)입니다.
> Claude(및 사람 개발자)는 전투/카드/토너먼트 관련 작업 전에 이 문서를 먼저 읽고, 변경이 생기면 이 문서를 같이 갱신합니다.
>
> 구성: ① 한 줄 요약 → ② 참고작(이누야샤 데몬 토너먼트) 룰 분석 → ③ 우리 게임의 설계 명세(의도) → ④ 현재 구현 상태(코드 기준) → ⑤ **명세 ↔ 구현 차이 & 미결정 사항** → ⑥ 용어집.
>
> ⚠️ **가장 중요한 섹션은 ⑤번입니다.** "설계 명세"와 "현재 코드"가 여러 지점에서 다릅니다. 작업 시작 전 반드시 ⑤를 확인하세요.

## ① 한 줄 요약

*이누야샤 데몬 토너먼트*처럼 **1:1 토너먼트 기반 카드 전투**를 핵심으로, 캐릭터 선택·성장과 짧은 플레이 세션을 결합한 그리드 액션 대전 게임.

- 장르: 턴제 / 카드 선택 / 전술 격투
- 한 턴에 **카드 3장**을 골라 순서대로 실행, 두 파이터가 동시에 진행
- HP가 0이 되면 승패 결정 → 다음 상대로 진행하는 토너먼트(건틀릿) 구조

## ② 참고작 분석 — Inuyasha: Demon Tournament

> 우리 게임의 "게임 방식"은 이 플래시 게임과 동일하게 가는 것이 목표입니다. 아래는 웹 리서치로 확인한 원작 룰입니다(출처는 문서 맨 아래).

### 개요
- 애니메이션 *이누야샤* 캐릭터로 싸우는 **턴제 1:1 전술 격투**. (단순화된 Tactics Arena Online + Street Fighter 느낌)
- 플레이어와 CPU가 **매 라운드 카드 3장을 선택**하고, 그 카드들이 **하나씩 차례로 공개되며** 행동이 펼쳐진다(양측 동시 진행).

### 전장(그리드)
- 2D 격자 전장에서 두 파이터가 마주 본다(가로로 긴 6열 × 4행 격자).
- 각 캐릭터는 격자 위 한 칸을 차지하고, **이동 카드**로 격자를 이동한다.

### 카드 구성
모든 카드에는 다음 정보가 표시된다: **이름 / 데미지(DM) / 에너지 비용(EN) / 3×3 사거리 그리드**.
- **3×3 그리드 표기**: 정중앙 칸 = 캐릭터 자신의 위치. 강조(빨강)된 칸 = 그 행동이 영향을 주는 범위.
- **이동 카드 (Movement)**: 카드 하단 화살표 방향으로 이동.
- **공격 카드 (Attack)**: 에너지를 소모, 상대가 사거리 칸 안에 있으면 데미지를 입힌다.
- **가드 카드 (Guard)**: 그 턴에 받는 피해를 **최대 15까지** 막는다.
- **에너지 회복 카드 (Energy)**: 에너지 바를 **15** 회복.

### 자원
- **에너지(EN)**: 공격/이동 등에 소모. 카드마다 비용이 다름. (라운드 사이 일부 회복)
- **HP**: 공격이 적중하면 카드 데미지만큼 차감. 0이 되면 패배.

### 진행/보상
- 적을 쓰러뜨리면 **사혼의 구슬 조각** 획득 + **미스터리 카드 5장 중 1장 선택**하여 덱에 추가(특수 공격 / 이동 강화 / 회복 등).
- 토너먼트(사다리) 형태로 점점 강한 상대와 대결.

### 캐릭터(원작)
이누야샤, 카고메, 셋쇼마루, 미로쿠, 산고, 키쿄, 나라쿠 등. 캐릭터마다 고유 기술/특수공격 보유.

> 📌 우리 게임은 원작 캐릭터를 **그대로 쓰지 않고** 오리지널 캐릭터로 대체했습니다. 룰·시스템만 차용합니다(저작권 회피 + 오리지널리티). 테마는 **다크 판타지**이고, 현재 로스터는 **3직업**(CAIRN 전사 / SABLE 궁수 / DIRGE 마법사)입니다. 그 전에는 6종 체계였고(다크 판타지 VESPER/MAUL/DIRGE/SABLE/CAIRN/PYRE ← 사이버 아레나 VOLT/TITAN/NOVA/CIPHER/AEGIS/EMBER), 대응표는 ④ "3직업 개편"·"로스터 리스킨"에 있습니다.

## ③ 설계 명세 (의도) — 사용자가 정의한 룰

> 이것은 **목표로 하는 디자인**입니다. 현재 코드와 다른 부분이 있으며, 차이는 ⑤에 정리.

### 게임 흐름
1. 캐릭터 선택
2. 각 캐릭터는 **공용 카드 + 고유(직업) 카드**를 가진다.
3. 공용 카드: 이동 카드, 가드 카드, 에너지 회복 카드
4. 고유 카드: 공격 카드 (에너지를 써서 데미지. 카드마다 **범위 / 에너지 / 데미지**가 다름)
5. **매 턴 카드 3장 선택**
6. 상대와 함께 3장을 **순서대로** 실행
   - **카드 실행 순서: ① 이동 카드 → ② 수비(가드) 카드 → ③ 공격 카드**
7. HP가 다 닳으면 승리 또는 패배

### 시작 배치 (2D 격자)
```
+----+----+----+----+
| P1 |    |    | P2 |   ← 두 캐릭터가 격자 양끝에서 마주 보고 시작
|    |    |    |    |
+----+----+----+----+
```
(구현 확정: **4행 × 6열**(2026-08-05, 3행에서 늘림). PvP·봇전은 양 끝 row 1 고정, 런은 양쪽 다 자기 끝열 네 칸 중 무작위로 시작. 자세한 근거는 CLAUDE.md "격자 3행 → 4행".)

### 카드 명세 (2026-07-03 갱신 — 공용/고유 이원화)

> 사용자 방침: **이동 카드는 모두 동일(공용)**. 공용에는 *별로 안 좋은* 공격·방어 카드도 포함되어 누구나 쓸 수 있는 바닥 라인을 이루고, **진짜 강한 카드는 각 캐릭터(직업)의 고유 카드**다. 고유 카드에는 다양한 특수 능력(넓은 범위, 강한 공격력, 때리면서 기력 흡수 등)이 붙는다. 추후 **뽑기/구매로 카드를 획득해 덱을 조합**하는 시스템으로 확장 예정(미구현).

#### 1) 공용 카드 (Common) — 의도적으로 약함
| 카드 | 에너지 | 효과 | 쿨타임 |
|---|---|---|---|
| 이동 `>` `<` `^` `v` (1칸) | 0 | 해당 방향 1칸 이동 | 0턴 |
| 이동 `>>` `<<` (2칸) | 0 | 좌/우 2칸 이동 | 1턴 |
| 내려치기 | 10 | 앞뒤 1칸 **10 데미지** (약공) | 0턴 |
| 돌팔매 | 10 | 앞뒤 2칸째 1칸씩 **10 데미지** (견제) | 0턴 |
| 방패 세우기 | 10 | **50 데미지 방어** | 1턴 |
| 버티기 | 10 | **30 데미지 방어** (약가드) | 0턴 |
| 에너지 회복 | 0 | **에너지 50 회복** | 0턴 |

#### 2) 고유(직업) 카드 — 직업마다 8~9장 + 직업 기본기 3장, 특수 능력 보유
캐릭터별 전용 카드. 대부분 공격이지만 종류 제한은 없다(예: AEGIS의 전용 가드 "아이언 커튼"). 공격 카드 특수 능력 목록(엔진 지원, 조합 가능):

| 능력 | 필드 | 효과 |
|---|---|---|
| 기력 흡수 | `drain: N` | 적중 시(가드로 막혀도) 상대 기력을 최대 N 빼앗아 흡수 |
| 흡혈 | `leech: N` | 피해를 실제로 입히면 체력 N 회복 |
| 관통 | `pierce` | 상대 보호막을 무시(소모시키지도 않음)하고 피해 |
| 넉백 | `push: N` | 적중 시 상대를 공격자 방향 기준 뒤로 N칸 밀어냄(벽·공격자 셀에서 멈춤) |
| 방벽 전개 | `selfShield: N` | 기력 지불 성공 시 자신 보호막 +N (빗나가도 적용) |
| 반동 | `recoil: N` | 기력 지불 성공 시 자신 체력 -N (빗나가도 적용) |

> 핵심: **선택한 3장을 정해진 순서(이동→수비→공격)대로 실행하여 그에 맞는 행동을 하는 것**이 가장 중요한 메커니즘.

## ④ 현재 구현 상태 (코드 기준)

> ⚠️ 아래는 **실제로 코드에 들어가 있는 동작**입니다. ③의 의도와 다른 부분이 있으니 ⑤와 함께 보세요.

### 기술 스택 / 실행
- **React 19 + TypeScript + Vite** (SPA, 단일 캔버스형 무대).
- 개발: `npm run dev` · 빌드: `npm run build` · 타입검사: `npm run typecheck`
- 외부 게임 엔진 없음. 전투는 순수 TS 클래스(`CardBattle`)로 시뮬레이션하고 React로 렌더.

### 화면 흐름 (`src/App.tsx`)
**타이틀이 로그라이크 입구다**(2026-08-04): `title →(게임 시작)→ run-start → run-map → …`.
단판은 PVP 아래로 내려갔다: `title →(PVP)→ deck-select → mode-select →` 봇전 `fight → result` 또는 온라인 `mp-lobby → mp-fight → mp-result`.
- ⚠ **건틀릿(대진표) 모드는 없어졌다.** 단판 전환 뒤로 쓰이지 않던 `game/tournament.ts`·`BracketScreen`·`CharacterSelect`를 2026-08-04에 지웠다 — 부활시키려면 git 기록에서 셋을 함께 꺼낸다.

### 전투 모델 (`src/battle/`) — **2D 격자** (방향 A로 구현 완료)
- **전장은 2D 격자**: `GRID_COLS = 6` × `GRID_ROWS = 4`(2026-08-05, 3행→4행). 셀 `{ col, row }`. col은 오른쪽으로, row는 아래로 증가.
- 시작 위치 `START_CELLS = [{0,1}, {5,1}]` — PvP·봇전은 이 고정값(양 끝 row 1)에서 마주 봄. **런은 양쪽 다 자기 끝열(col 0 / col 5)의 네 칸 중 무작위**로 서고(보스는 row 1 고정), 세로로 어긋난 채 개전한다. p0(플레이어)는 +col(오른쪽), p1(상대)는 −col(왼쪽)을 바라본다(`facing`).
- 자세(Stance) 개념은 **제거**됨 — 세로축은 이제 진짜 격자 이동(위/아래).
- 한 턴 = 카드 3장. **고른 슬롯 순서(1→2→3)대로** 해소하되, **한 슬롯 안에서** 나·상대 카드는 **타입 우선순위(이동 → 수비 → 공격)** 로 처리한다. 즉 "이동→수비→공격"은 전역 묶음이 아니라 *같은 슬롯 내 둘 중 누가 먼저 처리되는지* 정하는 규칙.
- **전투 생성 옵션(`BattleOpts`)** — 로그라이크 전용 훅. 미지정이면 예전 그대로라 **PvP·봇전·튜토리얼은 불변**이다: `chars`(스탯을 갈아끼운 CharacterDef — 몬스터), `passives`(유물 merge 결과), **`startHp`(2026-07-30, 층 사이 HP 이월 — 지정한 쪽만 그 체력으로 시작, 1..maxHp 클램프)**. 상세는 [ROGUELIKE.md](ROGUELIKE.md).

#### 카드 종류 (`CardKind`) — `src/battle/types.ts`
`move` | `attack` | `guard` | `energy` | `heal`(2026-07-23). 모든 카드에 `cooldown`(사용 후 잠기는 턴 수, 0/없음=재사용 가능).
- **이동 방향(`MoveDir`)**: 직교 4방향 + **대각선 4방향**(`up-right/up-left/down-right/down-left`, 2026-07-23). `MOVE_DELTA`가 델타를, `MIRROR_DIR`가 멀티 좌우 반전 짝을 정의(엔진은 정규 좌표, `BattleScreen.faceCard`가 side1 표시 라벨만 미러).
- **힐(`heal`)**: 기력을 체력으로 바꾸는 지원 카드(`c-repair`: `healCost:20`→`healHp:20`, 쿨1). 엔진 `resolvePrep`에서 처리(기력 부족 시 `nofuel`), 회복량은 `Step.heal`로 실어 초록 `+N` 연출 재사용. `planAffordable`이 `healCost`를 계산 → UI가 못 내는 힐 카드를 선택 불가 처리.

#### 공용 카드 (`COMMON_CARDS`) — `src/battle/cards.ts` (2026-07-03 확장)
| id | 이름 | kind | 효과 | 에너지 | 쿨타임 |
|---|---|---|---|---|---|
| `m-right` / `m-left` / `m-up` / `m-down` | 오른쪽/왼쪽/위/아래 | move | 해당 방향 1칸 (`>`/`<`/`^`/`v`) | 0 | **0** |
| `m-right2` / `m-left2` | 오른쪽/왼쪽 대시 | move | 좌·우 2칸 (`>>`/`<<`) | 0 | **1** |
| `c-strike` | 내려치기 | attack | 앞뒤 1칸 **10 데미지** — 약한 공용 공격 | 10 | **0** |
| `c-shot` | 돌팔매 | attack | 앞뒤 **2칸째만** **10 데미지** — 약한 견제 사격 | 10 | **0** |
| `c-guard` | 방패 세우기 | guard | 기력 **10**(`GUARD_COST`) 소모, 이번 턴 피해 최대 **50**(`GUARD_BLOCK`) 흡수 | 10 | **1** |
| `c-brace` | 버티기 | guard | 기력 10 소모, 이번 턴 피해 최대 **30** 흡수 — 약가드 | 10 | **0** |
| `c-energy` | 원기 회복 | energy | 기력 **35**(`ENERGY_GAIN`) 회복 | 0 | **1** (2026-07-15 하향: 50→35, 쿨0→1) |
- ⚠ **약공 3장(`c-strike`·`c-shot`·`c-jab`)은 2026-08-04부터 플레이어의 기본 공격이 아니다** — 직업별 기본기(`CharacterDef.basics`, 아래 "직업 기본기" 절)가 그 자리를 대신한다. 여기 남아 있는 이유는 **몬스터 덱(`monsters.ts`)·보스 스크립트·검사 스크립트가 계속 쓰기 때문**이고, `c-shot`은 덱 빌더 선택 풀에도 남아 있다(빼면 그걸 고른 저장 덱이 조용히 줄어든다).
- 추가 페이싱 장치: **턴 시작 시 패시브 기력 회복 `ENERGY_REGEN = 20`** (양측, 최대치 cap. 2026-07-15 하향: 30→20 — "매턴 3공격" 억제). 명세에는 없던 디자인 보강 — 원기 카드가 쿨일 때 교착 방지.

#### 고유 카드 (직업별 8~9장, `src/data/roster.ts` — 필드명 `cards`)
공격 필드: `range`(타격 셀 오프셋 배열), `damage`, `energyCost`, `cooldown:0` + 특수 능력 필드(아래).
- **`range`의 오프셋 `{ df, du }`**: `df`=앞쪽 칸 수(+는 상대 방향), `du`=위쪽 행 수(+는 위). 엔진이 `facing`으로 `df`의 좌우를 뒤집어 실제 셀로 변환(`targetsOf`).
- 적중 조건: 상대 셀이 변환된 타격 셀 집합에 포함될 때.
- 범위 헬퍼: `fwd(n)`(앞 n칸), `beam(a,b)`(같은 줄 직선 빔), `both(n)`(앞뒤 n칸째), `beamBoth(a,b)`(앞뒤 대칭 직선), `bar(df)`(앞/뒤 df칸의 위·중·아래 세로줄, 음수 가능), `CROSS`(상하좌우 십자), `FORK`(앞뒤 대각선 네 갈래 X자 — 정면 사각).
- **양방향 규약(2026-07-14)**: 교차(대시로 뛰어넘기)가 의도된 룰이므로 **대부분의 공격은 앞뒤를 함께 커버**하고, 그 대신 한쪽 사거리를 줄인다(예: 앞 3칸 빔 → 앞뒤 2칸씩). 캐릭터마다 1~2장은 **전방 전용**(램 프레스·이온 랜스·노바 블래스트·널 사이펀·실드 배시·오버히트 블리츠)으로 남겨 방향 싸움이 유지된다. 카드 미니 범위표(`RangeChart`)는 -3..3 창으로 확장.
- **특수 능력**(`types.ts`의 `drain/leech/pierce/push/selfShield/recoil`, 엔진 `computeAttack`·`applyOutcome`이 적용, ③의 표 참고):
  - `drain`·`push`는 **적중 시**(가드로 막혀도) 발동. `leech`는 **피해가 실제로 들어갔을 때만**.
  - `selfShield`·`recoil`은 **기력 지불 성공 시** 발동(빗나가도 적용, 기력 부족 `nofuel`이면 미발동).
  - `pierce`는 보호막을 소모시키지 않고 통과(EMBER의 `shieldBreak` 패시브와 별개).
  - 넉백 방향은 공격자 `facing` 방향(벽/공격자 셀에서 멈춤). 동시 트레이드에선 두 공격 판정 후 넉백을 순서대로(호스트 먼저) 적용.
  - UI: 카드 하단에 능력 칩(`CardFace`의 `abilityTags` — 관통/기력흡수/흡혈/넉백/방벽/반동), 전투 중 반동은 자기 몸의 `-N`, 흡수는 대사창 `⚡+N`으로 표시.
- 캐릭터별 직업 콘셉트(각 고유 4장): **VOLT** 기력 흡수 스피드스터(포크 라이트닝 `FORK` X자·서지에 `drain`), **TITAN** 광역+넉백 브루저(램 프레스 `push:2`, 슬램 `push:1`), **NOVA** 초장거리 포격수(이온 랜스 `pierce`, 패시브 기력 +20), **CIPHER** 흡혈 암살자(사이펀 `leech+drain`, 페이즈 `leech`, 패시브 `lifesteal`), **AEGIS** 방패 하이브리드(잽·드라이브 `selfShield`, **전용 가드 "아이언 커튼"** 70방어/20기력/쿨2, 패시브 방벽 +20), **EMBER** 하이리스크 러셔(블리츠·인페르노 `recoil`, 패시브 `revive:50` — 잿불 부활).
- **수치 규약(2026-07-14)**: 게임에 노출되는 모든 수치(데미지·기력 비용·방어량·회복·HP·시작 기력)는 **10의 배수**로 통일 — 가독성 우선. #### 직업 기본기 — 공용 약공을 직업별로 가름 (2026-08-04)

3직업 개편 뒤에도 **기본 공격은 셋이 똑같았다**. 로그라이크는 공용 약공 3장(`c-strike`/`c-shot`/`c-jab`)으로 출발하고 직업 카드는 보상으로 버는 구조라, **직업을 골라도 1~5층이 같은 싸움**이었다("각 캐릭터 기본 공격이 다 똑같은 게 아쉽다"). 그래서 `CharacterDef`에 **`basics` 3장**을 새로 뒀다(공용 약공은 그대로 남아 몬스터·검사 스크립트가 계속 쓴다).

**총합 화력은 공용과 거의 같게 맞췄다** — 1층이 여전히 쉬워야 하므로. 차이는 **어디를 때리느냐**에 있다.

#### 턴 해소 순서 (`CardBattle.resolveTurn`) — `src/battle/engine.ts`
턴 시작: 가드 실드 0으로 초기화 → 양측 패시브 기력 +20(`ENERGY_REGEN`). 이어서 **슬롯 0→1→2 순서**로, 각 슬롯에서 그 슬롯의 두 카드(나·상대)를 **우선순위 `이동(0) < 수비(1) < 공격(2)`** 로 정렬해 낮은 쪽부터 처리:
- **이동(move)** — 해당 방향 이동. 벽에 막히면 멈춤. **상대 셀은 통과·정지 모두 가능 — 겹침 허용**(2026-07-14 변경, 기존 "멈출 수 없음" 규칙 폐지). 넉백(push)도 벽에서만 멈추고 공격자 셀 위로 밀 수 있다. 겹친 상태에서도 **대부분의 카드는 서로 때릴 수 있다**(아래 "밀착 타격"). 엔진 `applyMove`·AI 시뮬레이션·UI 미리보기(`applyMovePreview`) 모두 동일 규칙. 화면에선 겹친 두 파이터를 좌우로 **9px씩** 비켜 표시(`.fighter--stacked-*`) — 예전 26px은 셀이 좁은 폰에서 "한 칸 옆"으로 읽혀 2026-07-25에 축소.
- **수비(defense)** — `guard`(기력 10 지불, 실드 +50) / `energy`(기력 +35).
- **공격(attack)** — 정렬된 board(앞선 이동/수비 반영) 기준으로 판정. 사거리 밖=`whiff`, 기력 부족=`nofuel`, 적중 시 상대 실드부터 차감(전부 흡수되면 `blocked`).
- **밀착 타격(point-blank, 2026-07-25 · 2026-08-04 재집계)** — 어떤 카드의 `range`도 자기 셀 `{df:0,du:0}`을 덮지 않으므로, **겹친 상대는 사거리와 별개로 카드의 `pointBlank` 필드로 판정**한다. 기본값은 "맞는다"(`pointBlank !== false`) — **공격 카드 30장(공용 3 + 직업 기본기 9 + 직업 고유 18) 중 26장 = 87%가 밀착 타격 가능**. 사각은 4장: `c-shot`(돌팔매·두 칸째 전용 도넛) + 궁수의 `arc-mark`(기본기 저격)·`arc-venom`(저격)·`arc-rain`(시그니처). 런 전용까지 합치면 43장 중 36장(84%)이고 사각은 7장(위 4장 + `r-hook`·`r-tether`·`r-railgun`).
  - ⚠ **이 4장은 두 작업이 반대로 잡아당긴 결과다.** 사거리 대칭화(2026-08-03)가 궁수 사각을 4장 → 2장으로 줄여 "붙으면 궁수가 죽는다"는 약점 설계가 절반으로 얇아졌는데, 직업 기본기(2026-08-04)가 `arc-mark`를 사각으로 넣으며 3장으로 되돌아왔다. 두 변경은 **서로 모르는 채 진행됐다**(각각 다른 갈래에서 작업) — 지금 수치는 합친 뒤 실측한 것이지 어느 쪽이 의도한 값이 아니다.
  - ⚠ **궁수 기본기 셋을 다 사각으로 만들면 안 된다.** 기본기는 런 시작 덱이라, 셋 다 사각이면 붙은 상대에게 아무것도 못 해 1층에서 막힌다. 사각은 `arc-mark` 한 장에만 둔다.
  - 카드 UI는 두 가지를 함께 보여 준다 — 사각인 카드엔 **`밀착사각` 능력칩**(`CardFace.abilityTags`), 밀착이 되는 공격 카드엔 사거리 그림 가운데 칸에 **테두리 표시**(`.rc--pb`). 그전엔 가운데 칸이 늘 비어 보여 "3칸인데 2칸처럼" 읽혔다.
  - 엔진 `computeAttack`·AI `hits()`·UI 범위 표시(`attackCells`의 `foe` 인자)가 같은 규칙을 공유하며, AI는 밀착 타격 수단이 있으면 겹침을 피하지 않고 오히려 올라탄다(`canPointBlank`).
- **한 슬롯에 양측 다 공격**이면(둘 다 우선순위 2) **같은 판에서 동시에 계산**한다 — 사거리·실드·상태이상은 둘 다 "맞기 전 판"을 보므로, 먼저 맞았다고 사거리가 바뀌지 않는다(상호 트레이드).
  - **적용은 순서가 있다(2026-08-04 변경)**: **쓰러뜨리는 쪽을 먼저 적용하고, 이미 쓰러진 쪽은 그 턴에 때리지 못한다.** 전엔 둘을 통째로 동시 적용해서 **체력 0이 된 상대의 공격이 그대로 들어왔다**("적을 죽였는데 그 적이 때려서 피해를 입는다" 신고). 죽은 쪽의 카드는 스텝 자체가 나가지 않는다.
  - ⚠ **서로를 쓰러뜨리는 진짜 동시 KO만 예외**로 둘 다 적용한다. 그래야 아래 타이브레이크·무승부가 그대로 살아 있고, 둘 중 누구를 먼저 놓느냐로 승자가 갈리는 비대칭(호스트 유리)이 생기지 않는다. 랜덤 없음 → 멀티 락스텝 안전.
  - 이 변경은 **트레이드에서 받는 피해를 줄이므로 밸런스가 움직인다** — 도입 시 런 클리어율 23.6%→30.3%, 캐릭터 밴드 1.7→7.2%p로 벌어져 `SIGNATURE.runEffect`를 재조정했다(궁수 `lifesteal` 5→4·`maxHpBonus` 40→28, 전사 `maxHpBonus` 34→29 → 밴드 2.4%p·클리어율 27.5%). 여기를 또 건드리면 `npm run sim:run -- --sweep`을 다시 돌릴 것.
- 그 외엔 낮은 우선순위 카드가 먼저 → 다음 카드는 갱신된 board를 본다(예: 내가 먼저 이동하면 상대 공격을 회피, 상대가 먼저 가드하면 내 공격을 경감).
- 각 슬롯 처리 후 HP가 0 이하면 종료. **동시 KO 타이브레이크(2026-07-15)**: 둘 다 0이면 **그 턴 시작 시점의 HP 비율(HP/maxHp)이 높았던 쪽이 승리**, 정확히 같을 때만 무승부(`winner=null`). 랜덤 없음 → 락스텝 안전. (도입 근거: AI 시뮬에서 동시 KO 무승부가 전체의 16%까지 치솟음 → 사실상 0%로.)

이 "슬롯 내 우선순위"가 명세의 의미다: *내 카드 3장은 고른 순서대로 실행*되고, 각 슬롯에서 *나와 상대 중 누가 먼저인지*만 이동→수비→공격으로 정해진다.

턴 종료: **전장 붕괴 판정**(아래) → 쿨타임을 1씩 감소시킨 뒤, **이번 턴 사용한 cd≥1 카드를 풀 쿨타임으로 잠금** → `turn += 1`. `planAffordable`은 **선택한 슬롯 순서대로**(회복·가드·공격의 기력 증감을 순서대로) 지불 가능 여부를 검사.

#### 전투 연출 — 공격 모션 · 필살기 컷인 (2026-07-23)
"앞뒤로 미끄러지기만 해서 루즈하다"는 피드백에 대응한 연출 레이어. **룰·수치는 건드리지 않는다**(순수 표현).
- **공격 모션**: 카드의 `fx` 종류별로 다른 동작(`ui.css`의 `atk-melee/atk-cast/atk-rush/atk-quake`). 근접은 웅크렸다 파고들고, 사격(`bolt/orb/flame`)은 기를 모았다 내지르고, `rush`는 잔상을 끌며 크게 돌진, `quake`는 솟구쳤다 내려찍는다. `FighterSprite`가 `is-atk-<fx>` 클래스를 붙여 선택. ⚠ 키프레임은 반드시 `scaleX(var(--flip))`을 유지해야 한다(빼면 공격 때마다 캐릭터가 뒤집힘).
- **타격감**: 모든 적중에 충격파 링(`.fx::before`), 근접엔 초승달 궤적(`.fx::after`). 피해 ≥ `SHAKE_DAMAGE`(22)면 판 전체가 흔들린다(`.board.is-shaking`).
- **필살기 컷인**: `signature: true` 카드가 발동하면(기력 부족 `nofuel` 제외) 타격 **직전에** 전투 화면 전체를 `CUTIN_MS`(1.75초) 동안 덮는다 — 대각 색띠가 쓸고 지나가며 대형 초상(`buildPortraitSvg`) + "〈캐릭터〉 · 필살기" + 기술명이 꽂힌다. 발동자가 나면 `cutin--me`, 상대면 `cutin--foe`(초상이 반대쪽으로). 구현은 `BattleScreen`의 `cutIn` 상태 + `ui.css`의 `.cutin*`.
- **멀티 안전**: 컷인·모션은 `resolveTurn` 결과(steps)를 보고 재생만 하므로 양 피어가 동일하게 재생 — 락스텝 결정론에 영향 없음. 다만 한 턴 해소 시간이 필살기당 1.75초 늘어난다(온라인 턴 타이머는 *선택* 단계에만 돌아 무관).

#### 전투 카드 표기 — 압축(compact) (2026-07-23)
`CardFace`에 `compact` prop 추가. **전투 화면(손패·슬롯)에서만** 켜서 설명문(`cardface__desc`)을 빼고 **이름 → 수치(⚔데미지 ↦사거리 ⚡기력, 가드는 방어·기력) → 범위표** 순서로만 보여준다(`.cardface--compact`가 flex `order`로 수치를 범위표 위로). 전투 중엔 설명을 읽을 겨를이 없고 빠르게 고르는 게 우선이라는 판단. **덱 빌더·도감은 `compact` 없이 설명 그대로** — 카드를 익히는 화면이라 설명이 핵심.
- **아이콘은 조연**: 종류 아이콘(⚔🛡⚡✚)은 압축 카드에서 우상단 구석의 작은 표식으로 `absolute` 배치(12px·불투명도 0.5). 대신 이름 18px·수치 15px·범위표는 카드 폭을 꽉 채워 "보자마자 범위·공격력·기력"이 읽히게 한다.
- **예외 — 이동 카드**: 화살표가 곧 정보라 구석 아이콘 대신 본문 가운데에 큰 화살표(`cardface__moveart`, 40px)를 넣는다. 수치·범위표가 없어 비어 보이던 문제도 해결.
- 슬롯(116px)은 손패(138px)보다 좁아 `.slot .cardface--compact`에서 이름 13px·수치 12px로 한 단계 줄여 수치가 한 줄에 들어가게 한다.
- 설명이 빠진 만큼 손패 카드 높이를 202→146px, `.cards` 높이를 378→322px로 줄여 **남는 세로를 보드에 돌려줬다**(격자가 커져 위치 싸움이 잘 보인다).

#### 카드 선택 미리보기 — 상시 유지 (2026-07-23)
카드를 고르는 동안 **지금까지 고른 플랜의 결과**를 보드에 계속 띄운다(`BattleScreen`의 `planPreview`). 슬롯을 1→3 순서로 훑으며 이동 카드는 위치를 옮기고, 공격 카드는 *그 시점 위치* 기준 타격 셀을 계산 → 유령(`.fighter--ghost`)은 최종 예상 위치에, 빨간 셀은 공격 범위로 표시.
- **위치는 누적, 공격 범위는 누적하지 않는다**(2026-07-23 수정). 이동은 순서대로 쌓여 최종 위치를 보여주지만, 빨간 칸은 **마지막에 고른 공격 한 장의 범위만** 남긴다 — 여러 공격의 범위가 겹쳐 뜨면 어디를 때리는지 읽을 수 없다는 피드백. 새 공격을 고르면 그 공격 기준으로 교체된다.
- **꺼지는 조건은 슬롯이 전부 빌 때 + 실행(제출) 후**. 카드를 놓아도, 마우스를 떼도, 가드·원기처럼 위치와 무관한 카드를 올려봐도 예시는 남는다(예전엔 호버에만 묶여 배치 즉시 사라졌다). 단 **`phase !== 'select'`면 그리지 않는다** — 실행을 눌러도 슬롯은 해소가 끝날 때까지 채워진 채라, 이 조건이 없으면 진행 중인 전투 위에 예시가 겹쳐 남는다.
- 카드에 마우스를 올리면 그 카드 기준 미리보기가 **일시적으로 덮어쓰고**, 떼면 플랜 미리보기로 복귀. 호버 시엔 그 카드가 놓일 슬롯(`hoverSlot`) *앞*의 이동만 반영해 "이 카드를 넣으면 어디서 터지는지"를 보여준다.

#### 전장 붕괴 — 열(column) 기반 점진 축소 (2026-07-13 도입 → 2026-07-16 열 축소 → **2026-08-05 "독안개"에서 개편**)
무한전(도망·회피 반복)을 확실히 끝내는 페이싱 장치. **양 끝 열부터 안쪽으로** 무너져 결국 판 전체를 덮는다(세로 이동은 끝까지 자유).

**왜 안개가 아니라 붕괴인가(2026-08-05)**: 판이 6×3뿐이라 이 장치가 실제로 하는 일은 "안개가 낀다"가 아니라 **"설 자리가 줄어든다"**였다. 사용자 피드백("차라리 전장이 작아지는 느낌이면")을 받아 연출·이름·색을 바닥이 무너지는 쪽으로 바꿨다. 보라 안개 → **갈라진 붉은 바닥**(`.cell--fog`, 클래스 이름은 참조가 많아 남겼다).

- ⚠ **무너진 칸에도 들어갈 수 있다(소프트 위험지대).** 벽으로 막지 않는 이유가 셋이다:
  ① 마지막 단계는 **전 칸**이 무너진다 — 막으면 설 자리가 0이 된다.
  ② 넉백·끌어당김·돌진이 상시로 위치를 옮긴다. 막힌 칸이 생기면 "밀렸는데 갈 곳이 없다"를 엔진 곳곳에서 따로 처리해야 하고, 그게 곧 룰 분기 = 락스텝 위험이다.
  ③ 궁수의 정체성이 "거리를 사는 것"이다. 강제로 좁히면 붙어야만 하는 판이 되어 3직업 약점 설계가 무너진다.
  → **체력을 내고 거리를 사는** 선택으로 남긴다. `npm run check`의 "무너진 칸으로 이동이 막히지 않는다"가 이걸 지킨다.
- **진행**: `COLLAPSE_START_TURN=6`에 stage 0 = **col 0·5**. `COLLAPSE_STEP_TURNS=3`턴마다 한 단계씩 안으로: **9턴** stage 1 = col 0·1·4·5, **12턴** stage 2 = col 0~5(**전부**). `collapseStageAt(turn)`이 단계를, `isCollapsedCell(cell, turn)`이 무너짐 여부를 계산.
- **피해**: **턴 종료 시**(3슬롯 해소 후) 무너진 열에 서 있으면 피해. **단계가 오를수록 아프다** — `COLLAPSE_DAMAGE = [10, 16, 24]`(옛 독안개는 전 단계 10 고정). 실드·피해감소 미적용(고정)이지만 유물 훅 `collapseResist`만큼은 깎인다. HP 0 가능(둘 다 0이면 동시 KO 타이브레이크).
- **경고**: `collapseEscalatesNext(turn)`이 true인 턴(5·8·11턴)에 HUD 배지 — 5턴 "다음 턴부터 전장이 무너진다!", 이후 "다음 턴 붕괴 확대!". 판에서도 **다음 턴에 무너질 열**에 금이 미리 그어진다(`.cell--fog-next`).
- **종결 보장**: 12턴이면 모든 열이 무너져 어디 서 있어도 매 턴 -24 → 게임이 반드시 끝난다.
- ⚠ **AI는 판 전체가 무너진 뒤에는 도망치지 않는다**(2026-08-05 수정). 그전엔 갈 곳이 없는데도 매 슬롯을 중앙으로 걷는 데 써서, 마지막 단계부터 AI가 아예 공격을 멈췄다 — 무한전을 끊으라고 넣은 장치가 오히려 판을 늘리고 있었다.
- 구현: 상수·판정은 `types.ts`(`COLLAPSE_START_TURN/COLLAPSE_STEP_TURNS/COLLAPSE_DAMAGE/collapseStageAt/isCollapsedCell/collapseDamageAt/isFullyCollapsed/collapseEscalatesNext`), 적용은 `engine.resolveTurn` 끝(랜덤 없음 → **멀티 락스텝 결정론 유지**). 연출 `Step{phase:'collapse', recoil:N}`.

⚠ **판 위의 연출 레이어는 클릭을 먹으면 안 된다**(2026-08-05, 같은 신고에서 나온 진짜 원인). 이동은 칸을 눌러서 하는데 `.fighter`가 `pointer-events: auto`로 남아 있어, **파이터 스프라이트가 덮은 윗줄 칸은 눌러도 반응이 없었다**(스프라이트는 발밑 기준이라 위 칸을 통째로 가린다). 상대가 가장자리에 서 있을 때 특히 "무너진 칸으로 이동이 안 된다"로 보였다. `.fighter`에 `pointer-events: none`을 걸어 고쳤다 — 판에 새 오버레이를 얹을 땐 반드시 같이 걸 것.

#### 지형 — 바위 (2026-08-05)

판이 빈 격자뿐이라 어느 전투나 "가로로 붙었다 떨어졌다"만 반복된다는 문제에서 나왔다(사용자 요청: "몇몇 맵은 지형이 좀 다르게… 중간에 바위를 세워서 그 앞을 뚫고는 지나갈 수 없다던가"). **런(싱글) 전용**이다.

**규칙은 셋뿐이다 — 늘리지 않는다.**
- ① **못 들어간다.** 이동·이동공격(`dashForward`)·넉백·끌어당김이 바위 앞에서 멈춘다. **벽과 같은 자리**(`canStand`)에서 처리되므로 새 룰 분기가 거의 안 생긴다.
- ② **사격선을 끊는다.** 공격자와 목표가 **같은 줄이거나 같은 열**일 때, 사이에 낀 바위가 그 칸을 가린다(`shadowRock`). **대각으로 어긋난 칸은 안 가린다** — 임의의 선분을 긋는 규칙(Bresenham 등)은 6×4 격자에서 판정이 눈에 안 읽히고, "가로·세로로 곧게 이어질 때만 막힌다"는 그림만 보고 바로 안다. 덕분에 **줄을 옮기는 것**이 언제나 우회로로 남는다.
- ③ **부술 수 있다.** 체력이 있다(`ROCK_HP = 50`, 무대마다 34~62). 공격이 덮은 칸에 선 바위 **그리고 그 공격을 가로막은 바위**가 피해를 받는다 — 후자가 있어야 사거리가 짧은 카드로도 결국 길을 뚫는다. 바위 피해엔 저체력·처형 배율과 상태이상 시너지를 얹지 않는다(지형이지 사람이 아니다).

**관통은 예외다.** `pierce` 카드와 유물 `alwaysPierce`는 바위를 무시하고 그 뒤를 그대로 때린다(바위도 안 깎는다). ⚠ 이게 **궁수·마법사의 답**이다 — 사격선을 끊는 규칙은 원거리 직업에게만 세금이라, 관통이라는 출구가 없으면 지형이 곧 직업 차별이 된다.

**처박기 기절.** 밀어낼(또는 끌어올) 곳에 바위가 서 있어 **한 칸도 못 움직이면** 그 상대는 **1턴 기절**한다(`slammed`). ⚠ **벽은 그렇지 않다.** 판 가장자리는 늘 거기 있어서 벽까지 포함하면 "구석에 몰린 상대를 매 턴 기절"이 되고, 그건 지형을 만든 대가가 아니라 그냥 좌석 운이다. 바위는 누군가 세웠거나 그 층이 준 것이라 **밀어붙일 곳을 골랐다**는 판단에 값을 치르는 게 맞다. 한 칸이라도 밀리면 기절하지 않는다.

**붕괴와의 관계**: 무너진 칸의 바위는 **같이 무너진다**. 남겨 두면 판이 좁아지는 속도에 지형이 곱해져, "무너진 칸에도 들어갈 수 있다"는 붕괴 설계의 안전판이 바위 때문에 사라진다(밀려날 곳도 도망칠 곳도 없는 판).

**배치 — 누가 데려오는가 (2026-08-07 개편)**: 2026-08-05에는 지형이 **무대**에 붙어 있었다. 1층 묘지부터 비석 둘이 서 있어서 **첫 전투부터 판이 막혀 있었고**, 사용자 신고가 그 지점이었다 — *"바위가 처음부터 나오는 건 좀 별로. 중간 보스 또는 골렘 이런 몇몇 애들한테 나오도록 했으면 합니다."* 지형이 **분위기**가 아니라 **그 적의 능력**이 되면, 판이 막힌 것 자체가 "이번 상대는 다르다"는 신호가 된다. 그래서 `terrainFor`는 이제 이 순서로 판정한다:

1. 몬스터가 `MonsterDef.terrain`을 가졌으면 그 배치 — **골렘**(`rubble`, 몸이 곧 돌인 유일한 몬스터라 일반 전투에도 데려온다) · **가디언**(`pillars`, 좁은 문 + 거북이 성격) · **화염군주**(`lavaslab`, 굳은 용암)
2. 보스 전용 무대면 **빈 판** — 심연(오버로드)은 "도망칠 수 없다"가 정체성이라 엄폐물이 컨셉과 부딪히고, 성소(수호기사)의 바위는 보스가 직접 세워야 「석벽 소환」이 무슨 일을 한 건지 보인다
3. 그 밖의 **엘리트 칸**이면 `rubble` — 첫 엘리트가 7층이라 **바위를 처음 보는 것도 그때**다
4. 일반 전투는 **빈 판**

배치 표는 `run.ts`의 `TERRAIN`(옛 `SCENE_TERRAIN`) — `rubble` 잔해 2(34) · `pillars` 기둥 2(62, 같은 열에 세워 **좁은 문**) · `lavaslab` 1(25). 원칙 셋을 `npm run check`가 지킨다: 열을 통째로 막지 않는다 · 끝열(시작 자리이자 가장 먼저 무너지는 열)에 두지 않는다 · **대부분의 전투는 빈 판이다**(전부 지형이면 지형이 배경이 된다).

**지형 카드 — 판을 내가 바꾼다 (2026-08-07)**: 그전까지 바위는 무대가 주는 것이라 플레이어에겐 순수한 방해물이었다. 전사 **「돌기둥 세우기」**(`war-menhir`, 앞 1칸)와 마법사 **「석순 소환」**(`mag-menhir`, 앞 2칸)이 `raiseRocks: {where:'ahead', dist}`로 판에 바위를 세운다. 전사는 "떼어내고 막는다"(밀착 싸움에 얹힌다), 마법사는 "오지 못하게 한다"(낮은 단일 화력을 거리로 메우는 정체성).

- ⚠ **앞뒤 대칭 원칙의 진짜 예외다.** 뒤에도 세우면 내 등 뒤를 내가 막아 도망칠 곳이 사라진다 — 방향이 곧 뜻인 카드라 대칭이 성립하지 않는다. 같은 이유로 `pointBlank: false`다(겹친 상대를 때리면 그 상대가 **바위를 세울 칸으로** 밀려나 카드가 자기 일을 못 한다).

#### 상태이상 — 전면 재정의 (2026-08-07, 사용자 확정 규칙)

##### 먼저: 턴 ≠ 라운드
사용자가 용어를 확정했다. **턴 = 양쪽이 카드를 한 장씩 내는 것**(코드의 `slot`, 한 라운드에 3번), **라운드 = 카드 3장을 고르고 다 쓰는 것**(코드의 `BattleState.round`, `resolveRound` 한 번). 그래서 **한 라운드 = 3턴**이다. 예전 코드·문서의 "N턴"은 거의 전부 지금 말로는 **라운드**였다 — `state.turn`·`resolveTurn`·`STATUS_TURNS`·`COLLAPSE_START_TURN`을 전부 `round`로 갈았다.
- ⚠ **아직 `turn`이라 불리는 것 둘**: 패시브 훅 `turnEnergy`/`turnShield`(유물 164종이 참조하는 이름이라 안 건드렸다 — 실제로는 라운드마다다)와 온라인 프로토콜의 `msg.turn`(전선 위 필드).

##### 왜 바꿨나
전엔 종류가 여섯인데 **실제로 하는 일이 셋뿐**이었다 — 독과 화상은 출처만 다른 똑같은 지속피해였고, 빙결은 이동만 막았다. 무엇에 걸렸는지가 판에서 안 읽혔다. 이제 **각각이 다른 자리를 때린다**: 걸린 상태이상이 곧 "이번 라운드에 뭘 하면 안 되는가"다.

| 상태이상 | 언제 아픈가 | 수치 | 지속 | 보호막 |
| --- | --- | --- | --- | --- |
| **중독** `poison` | **몸이 움직이거나 때릴 때** — 이동 1칸 / 공격 1장 / 넉백 1칸 | 겹당 3 (`POISON_TICK_DAMAGE`) | N라운드 · 겹마다 따로 | **관통** |
| **화상** `burn` | **맞을 때** — 피격 1회마다 | 겹당 +5 (`BURN_HIT_DAMAGE`) | N라운드 · 겹마다 따로 | **관통** |
| **빙결** `frozen` | 이 라운드 남은 카드를 못 냄 | 깨뜨린 타격에 +5 (`FREEZE_SHATTER_BONUS`) | **이 라운드만** | 파쇄 피해는 관통 |
| **기절** `stunned` | 이 라운드 남은 카드를 못 냄 | — | **이 라운드만** | — |
| **속박** `bind` | 이동 카드만 무효 | — | **이 라운드만** | — |

##### 라운드 한정 셋 — 이 개편의 핵심
빙결·기절·속박은 **걸린 그 라운드 안에서만 산다**(`isRoundLock`). 슬롯 1에서 걸리면 슬롯 2·3을 막고, **슬롯 3에서 걸리면 아무것도 못 막고 사라진다**(그래서 마지막 슬롯에 기절기를 넣을 이유가 없다 — 사용자 확정). 라운드 시작에 무조건 지워진다.
- ⚠ 그 결과 **카드를 고르는 시점에는 어떤 봉인도 걸려 있지 않다** → UI가 손패를 잠글 일이 없어졌다. 2026-08-05의 "넉백 당하고 나서 이동이 안 된다" 신고는 빙결이 라운드를 넘어와 이동을 막던 것이 정체였는데, 규칙이 바뀌며 **그 함정 자체가 사라졌다**(`BattleScreen`의 `frozen` 게이트와 `.cards__note` 안내를 제거).
- ⚠ **빙결 ≠ 기절**: 둘 다 봉인이지만 **빙결은 맞으면 깨진다**. 얼려 놓고 안 때리면 상대는 라운드 내내 못 움직이고, 때리는 순간 봉인이 끝나는 대신 그 타격이 5 더 아프다 — 때릴지 말지가 선택이 된다. 기절은 깨지지 않는 순수 봉인이다.
- 봉인된 슬롯의 카드는 **소모되지 않는다**(쿨다운도 안 돈다 — 애초에 낸 적이 없다). 엔진이 `plans` 복사본에서 비우고 `stun`/`frozen` 스텝을 싣는다.

##### 중첩 — 겹마다 따로 산다
`중독2`는 "2라운드짜리 **한 겹**"이고 `중독 3개`는 "**세 겹**"이라 이동 1칸에 9를 맞는다. 겹마다 남은 라운드가 다르므로 **합치지 않고 목록에 한 칸씩** 쓴다(합치면 서로 다른 지속을 못 적는다). 종류당 `STATUS_STACK_CAP=3`겹까지, 한 겹은 `STATUS_MAX_ROUNDS=3`라운드까지.
- **한 대에 한 겹.** 카드의 `poison`과 유물 `poisonOnHit`이 겹치면 **지속이 긴 쪽** 한 겹만 붙는다(유물 하나로 두 겹이 되면 안 된다).
- 꽉 찼으면 **가장 짧은 겹을 갱신**한다 — 상한에 닿아도 계속 때리면 유지는 끊기지 않는다.
- ⚠ **카드·유물의 숫자 의미가 바뀌었다.** `poison: 3`은 이제 "위력 3"이 아니라 **"3라운드"**다. 위력은 늘 고정(3/5)이고 `statusPowerPct`가 그 **한 겹의 위력**을 키운다.

##### 부여 조건과 관통
- 부여는 예전과 같은 규칙 — **보호막·경감을 실제로 뚫었을 때만**(`core > 0`). 가드에 완전히 막힌 타격으로는 아무것도 안 묻는다.
- 중독·화상·독안개·빙결 파쇄는 **보호막을 관통한다**(사용자 확정: "화상이나 독, 관통의 경우에는 보호막이 막을 수 없는 데미지"). 그래서 `computeAttack`은 피해를 둘로 나눠 들고 다닌다 — `core`(보호막·경감을 뚫은 몫, **on-hit 판정 기준**)와 `dmg`(= `core` + 화상 + 빙결 파쇄, 실제로 깎이는 총량). 흡혈·반사·기절·상태이상 부여는 전부 `core`를 본다.
- **중독이 세는 것은 이동 1칸과 공격 카드 1장뿐이다**(2026-08-07 2차 · 사용자 요청). 1차에선 이동만 셌는데, 붙어서 제자리 공격만 하는 몬스터에게 중독이 **아무 일도 하지 않아** 궁수 정체성이 성립하지 않았다. **수비·기력·회복·강화는 안 센다** — 중독에 걸리면 "버티는 것"만 공짜로 남는다는 게 이 규칙의 요점이다.
- **넉백으로 밀려난 칸도 센다**(2026-08-07 3차 · 사용자 확정). 즉 중독은 **어떻게든 몸이 옮겨졌으면** 아프다. 1차에선 "내가 낸 카드가 아니다"를 이유로 뺐었는데, 사용자 예시가 넉백 2칸 = 중독 6을 명시해 뒤집었다. 이동공격(`dashForward`)은 **공격 1 + 움직인 칸**을 둘 다 센다.

##### 넉백 — 처박기가 벽까지 확장됐고, 부분 차단에도 기절한다 (사용자 확정)
밀려날 곳이 막혀 있으면 넉백이 없던 일이 되는 게 아니라 **부딪힌다**: 못 밀린 칸마다 `KNOCKBACK_BLOCK_DAMAGE`(5) + **그 라운드 기절**. 그리고 **실제로 밀려난 칸은 중독이 문다.**
- 사용자 예시(검사로 그대로 재현): 중독 1겹인 상대를 넉백3으로 미는데 벽이 2칸 뒤 → 2칸 밀리고 1칸 막힘 → **5(넉백) + 6(중독 2칸) = 11 피해 + 기절**
- 예) 넉백3인데 바로 뒤가 판 끝 → 3칸 다 막힘 → **15 피해 + 기절**
- ⚠ 안전판이 두 번에 걸쳐 걷혔다. 2026-08-05까지는 **바위만** 처박기 대상이었고("가장자리는 늘 거기 있어서 포함하면 구석에 몰린 상대를 매 라운드 기절 — 지형을 만든 대가가 아니라 좌석 운"), 08-07 1차에서 벽을 넣되 기절을 "0칸일 때만"으로 좁혔다. 사용자 예시가 **부분 차단에도 기절**을 명시해 그마저 걷어냈다 — 그 결과 **벽을 등지고 싸우는 것 자체가 큰 위험**이 된 것이 지금 판의 성격이다. 되돌릴 일이 생기면 `applyOutcome`의 `slammed` 조건 한 줄이다.
- ⚠ 사용자가 제시한 원안은 칸당 10이었으나 "**넉백만 절반**"으로 확정 — ÷2 리스케일(2026-08-05) 이후 기본 공격이 5~7이라 칸당 10이면 넉백3이 강한 스킬 값(30)을 넘어선다.

##### 독안개 타일
전장 붕괴와 **같은 자리·같은 규칙**(라운드 종료 · 보호막 무시 · 랜덤 없음)이다. 다른 건 하나 — 붕괴는 시간이 만들고 안개는 **카드가 깐다**(`CardDef.fog` = 지속 라운드, 적중한 상대의 칸에 깔린다).
- 배선은 **궁수 계열**(사용자 결정): `arc-rain`(독의 비, 시그니처) 2라운드 · `r-plaguebolt`(역병 화살) 1라운드.
- **중독과 물린다** — 서 있으면 안개가 갉고 비키면 중독이 갉는다. 궁수의 "거리를 강요한다"가 처음으로 규칙으로 성립한다.
- ⚠ **런 전용이 아니다.** 궁수 카드가 깔면 PvP에서도 생기므로 `RULES_VERSION`에 걸린다(바위처럼 no-op으로 빠지지 않는다). 무너진 칸의 안개는 바위와 같은 이유로 함께 사라진다.

##### 힘(`empower`)
카드 `empower`가 쌓는 **전투 내내 유지되는 공격 보너스**(`BattleState.empowered`). 사용자 규칙 그대로 — 같은 적과 싸우는 동안 유지되고 **전투가 끝나면 0으로 돌아간다**(고블린에서 얻은 힘 5는 도끼병전에서 안 남는다). 2026-08-07부터 **버프 카드에서도** 붙일 수 있다. 표시명은 "각성" → **"힘"**.

##### 구현·검증
- 타입·상수 `types.ts`(`StatusKind`/`StatusEffect{rounds,power}`/`isRoundLock`/`isFullLock`/`isStacking`/`POISON_MOVE_DAMAGE`/`BURN_HIT_DAMAGE`/`FREEZE_SHATTER_BONUS`/`KNOCKBACK_BLOCK_DAMAGE`/`FOG_DAMAGE`/`FogTile`/`fogAt`)
- 적용·정산 `engine.resolveRound` — 라운드 시작에 `isRoundLock` 제거 → 슬롯마다 `lockedThisRound` 필터 → `tickPoisonOnMove`(이동 직후) → `computeAttack`의 `burnBonus`/`thaw` → `applyOutcome`(넉백 처박기·상태이상 부여·`layFog`) → 라운드 종료 `tickFog` → `tickStatuses`(지속만 깎는다, **피해 없음**) → 전장 붕괴
- ⚠ `tickStatuses`가 더 이상 피해를 주지 않는다 — 중독은 움직일 때, 화상은 맞을 때 이미 정산됐다. 라운드 종료에 갉는 건 **독안개와 전장 붕괴**(자리 값)뿐이다.
- 표시 `ui/cardAbility.ts`(아이콘·뜻)·`BattleScreen`의 `statusChips`(겹을 종류별로 묶어 그린다 — 그대로 그리면 같은 아이콘이 세 개씩 늘어선다)
- 검증 `npm run check`의 "상태이상"·"기절"·"지형" 절 — 중독의 이동 단위(1칸/대시 2칸/대각 1칸)·관통·중첩 상한, 화상의 피격 증폭·가드 관통, 빙결 파쇄, 속박, 독안개, 넉백 처박기(바위/벽/부분 차단/완전 이동)까지 단정한다.
- **`RULES_VERSION` 4 → 5.** `resolveRound` 출력이 통째로 달라진다.

##### 지속 연장 유물 — 런 전용 전설 6종 (2026-08-07 2차)
다른 상태이상 유물이 **위력**이나 **부여 확률**을 산다면, 이 여섯은 **시간**을 산다. 시간은 다른 모든 훅과 곱해지므로(중독 1라운드가 늘면 그 라운드의 모든 행동이 아프고, 화상 1라운드가 늘면 그 라운드의 모든 피격이 아프다) 값이 작아도 판을 바꾼다. 그래서 **전부 `legend`**로만 낸다 — 층 1에서 ≈6%, 층 15에서 ≈17%로 뽑히고 상점가 230이라 "이걸 노리고 굴리는" 빌드가 되려면 깊이 살아남아야 한다.

| id | 이름 | 효과 |
| --- | --- | --- |
| `hourglass` | 썩어드는 모래시계 ⏳ | 중독 +1라운드 · 중독·화상 위력 +25% |
| `everember` | 꺼지지 않는 잉걸 🔥 | 화상 +1라운드 · 상태이상 상대 피해 +12 |
| `sabbath` | 마녀의 안식일 🌙 | 중독·화상 각각 +1라운드 |
| `silentbell` | 침묵의 종 🔕 | **기절 +1라운드**(다음 라운드까지) |
| `glacialtomb` | 빙하의 관 🧊 | **빙결 +1라운드** · 전투당 4회 빙결 부여 |
| `grasproot` | 얽매는 뿌리 🕸 | **속박 +1라운드** · 받는 피해 -3 |

**봉인 연장이 성립하려면 라운드를 넘어갈 수 있어야 한다.** 그래서 봉인을 라운드 **시작**에 지우던 것을 없애고 라운드 **종료**의 `tickStatuses`에 맡겼다 — 기본 1라운드짜리는 결과가 완전히 같고(걸린 라운드의 남은 슬롯만 막고 사라진다), 지속이 2가 된 것만 다음 라운드까지 이어진다.

- ⚠ **무한 봉인을 막는 것은 `applyStatus`의 재부여 가드 한 줄뿐이다** — 이미 걸려 있는 기절·빙결·속박은 **다시 걸리지 않는다**. 그래서 사용자가 못박은 시나리오가 그대로 성립한다: **1라운드 기절 → 2라운드도 기절(그 안에 또 맞아도 갱신 안 됨) → 3라운드엔 반드시 일어난다.** 유물 하나로 판을 잠글 수 없다. `npm run check`가 세 라운드를 그대로 재현해 지킨다.
- ⚠ **훅 다섯을 유물 밖에 두지 말 것**(`poisonRoundBonus`·`burnRoundBonus`·`stunRoundBonus`·`freezeRoundBonus`·`bindRoundBonus`). 유물은 `mergeRelics`를 거쳐 런에서만 합쳐지고 PvP·봇전은 `relics.ts`를 import조차 하지 않으므로, 훅이 유물에만 있는 한 이 규칙이 PvP에 **존재하지 않는다** — 바위와 같은 근거로 `RULES_VERSION`을 안 올린다. 검사는 ROSTER·몬스터·희귀도(전부 legend)·보상 풀 네 가지를 단정한다.
- ⚠ **처박기 기절은 연장을 안 탄다** — 넉백은 이미 피해와 봉인 둘을 주는 자리라, 여기까지 늘리면 밀어내기 카드 한 장이 판을 통째로 잠근다.
- ⚠ **봉인이 라운드를 넘어오면 카드 선택 화면이 이유를 말해야 한다** — `BattleScreen`이 `lockedThisRound`로 손패 앞에 칩(💫/❄/🕸)을 세운다. 없으면 "실행했는데 아무 일도 안 일어난다"가 되고 그건 버그로 읽힌다. 단 **못 고르게 막지는 않는다**: 빙결은 같은 라운드 안에서 깨질 수 있어, 화면이 먼저 잠그면 낼 수 있었던 카드를 빼앗는 셈이 된다.

##### 밸런스 영향 (5시드 × 900런 `--sweep --path=random`)
개편 직후 **클리어율 33% → 20.6% · 밴드 0.86 → 9.3%p**로 무너졌다. 무너진 쪽은 궁수(16.9%)와 마법사(18.7%)다 — **중독·화상이 라운드마다 자동으로 갉던 지속피해가 아니게 됐기 때문**이다. 붙어서 제자리 공격만 하는 몬스터에게 중독은 거의 0이고, 화상도 "내가 때려야" 값을 한다.
- `SIGNATURE.runEffect`만 움직여 되돌렸다 — 전사 `maxHpBonus` 20→**42** · 궁수 23→**49**(+`poisonOnHit` 1→2) · 마법사 46→**50**(+`burnOnHit` 1→2). **DR·regen·thorns·lifesteal은 안 건드렸다**(÷2 스케일에서 정수 1이 너무 크다 — GDD ④ "리스케일" 참고).
- 결과 **밴드 0.80%p · 클리어율 ~32.7%**(ARCHER 33.1 / WARRIOR 32.8 / MAGE 32.3).

**2차(중독이 공격도 세게 된 뒤 + 연장 유물 도입)**: 궁수가 33.1 → **41.4%**로 튀었다 — 중독이 처음으로 "붙어서 때리기만 하는 몬스터"에게도 값을 하기 때문이다. 다시 `maxHpBonus`만 움직여 맞췄다: 전사 42→**48** · 궁수 49→**30** · 마법사 50→**57**. **홀드아웃 5시드 × 1200런**(튜닝에 안 쓴 시드) 결과 **밴드 0.78%p · 클리어율 ~34.2%**(MAGE 34.6 / WARRIOR 34.4 / ARCHER 33.8).
**3차(중독이 넉백도 세게 됨 + `bonusVsAfflicted` ÷2 수정)**: 같은 커밋에서 상반된 두 변화가 들어갔다 — 중독이 세지고, 상태이상 시너지 유물 8종이 절반이 됐다. 합치면 거의 상쇄돼 `maxHpBonus`만 조금 움직였다(전사 48→**50** · 마법사 57→**58** · 궁수 30 유지). **10시드 × 1200런** 결과 **밴드 0.60%p · 클리어율 ~33.0%**(MAGE 33.2 / ARCHER 33.0 / WARRIOR 32.6).
- ⚠ **`bonusVsAfflicted`가 ÷2 리스케일을 빠뜨리고 있었다**(2026-08-07 발견). 2026-08-05에 설명 스크립트는 숫자를 절반으로 내렸는데 값 스크립트가 이 필드를 매그니튜드로 인식하지 못해 **값만 그대로** 남았다 — 8종이 전부 표기의 2배로 때렸다(사냥꾼의 앙심 표기 +7 / 실제 +14). 사용자 결정으로 값을 절반으로 내려 표기에 맞췄다. 평면 가산이라 기본 공격 5~7인 지금 스케일에서 +14는 기본기 두세 대 값이었다.
- ⚠ **리스케일 스크립트가 놓친 필드가 또 있을 수 있다** — 매그니튜드를 새 훅으로 뺄 때는 `desc`의 숫자와 `effect`의 값이 같은지 눈으로 대조할 것.

- ⚠ **지금 궁수의 생존력은 최대체력이 아니라 "중독이 실제로 값을 한다"는 데서 온다**(체력 보너스가 49 → 30으로 내려갔다). 중독 규칙을 되돌리면 `maxHpBonus`부터 다시 올려야 한다.

#### 전투 표시 — 두 가지 연출 모드 (2026-08-12)

신고(궁수 플레이 중): *"중독이나 그런 것까지 있으니까 무슨 데미지가 들어갔는지 잘 모르겠고 그냥 후다닥 지나가니까 헷갈린다. 상태이상이 정말로 안 보인다. 순서도 잘 보였으면. 처음이나 기본값은 각각의 공격 전에 카드가 나와서 누가 뭘 냈는지 볼 수 있게 하고, 익숙해졌을 때 고수용으로 지금 이 세팅이었으면 좋겠다."*

**룰은 하나도 안 바뀐다.** 같은 라운드를 두 가지 속도로 보여줄 뿐이라 `RULES_VERSION`도 그대로다. 고르는 곳은 `src/game/settings.ts`(`BattlePace`), 저장은 기기 로컬 `gb-battle-pace`, 토글은 전투 HUD 가운데(🐢/⚡).

| | **차근차근**(기본값) | **빠르게**(고수용) |
| --- | --- | --- |
| 슬롯마다 카드 공개 | ✓ 양쪽 카드를 크게 1.25초 | ✗ |
| 화면 아래 | 양쪽 플랜 3장씩 + 전투 기록 | 예전 그대로(한 줄 상태) |
| 스텝 대기 | ×1.45 · 피해 뒤 +0.38초 | ×1 |
| 진행 순서 칩(①②③) | ✓ | ✓ |

- ⚠ **연출 길이는 라운드가 **시작할 때** 한 번 정한다**(`PACE_CFG`를 `paceRef`에서 읽어 지역 변수로 잡는다). 재생 도중에 토글을 눌러 템포가 갈리면 오히려 더 헷갈린다 — 바뀐 값은 다음 라운드부터다.
- ⚠ **타격까지의 선행 시간(`impactDelay`)에는 배수를 안 건다.** 그 값은 스프라이트 클립의 실제 프레임 번호라, 늘이면 모션이 끝난 허공에서 피해가 터진다. 늘어나는 건 언제나 **스텝의 꼬리**뿐이다.
- ⚠ **카드 공개는 입력을 삼키지 않는다**(`pointer-events: none`). 보스 컷인과 다른 점이다 — 이 구간엔 누를 게 없고, 삼키면 그 시간만큼 종료 버튼도 안 눌린다.

**피해 내역(`Step.bits`)** — "무슨 데미지가 들어갔는지 모르겠다"의 절반은 화면 문제가 아니라 **엔진이 안 알려주고 있었던 것**이다. 세 갈래가 숫자 없이 체력만 깎고 있었다:

| | 예전 | 지금 |
| --- | --- | --- |
| 화상·빙결 파쇄 | `damage`에 **합쳐져** 구분 불가 | `burn`·`shatter`로 갈라 적는다 |
| **처박기**(넉백이 막힌 몫) | `damage`·`recoil` 어디에도 없음 → **화면에 안 뜸** | `slam` |
| **가시 반사**(thorns) | 같음 — 안 뜸 | `thorns` |

- 화면은 갈래가 둘 이상이거나 평범한 타격이 아닐 때만 꼬리표를 붙인다(전부 붙이면 판이 글자로 덮인다). 전투 기록에는 항상 남는다.
- ⚠ **`bits`도 `slot`도 연출 전용 메타데이터**다(`slam`과 같은 급). 엔진은 이미 판에 반영한 값을 적어 줄 뿐이라 지워도 결과가 같고 — 같은 시드 스윕이 소수점까지 동일하다 — 그래서 `RULES_VERSION`을 안 올린다. 다만 **합계는 그 스텝에서 실제로 깎인 체력과 같아야 한다**: `npm run check`의 "피해 내역·슬롯 번호" 15건이 지킨다.

**상태이상 가시성** — 칩을 키우는 것만으로는 부족했다(발밑 칩은 스프라이트·불꽃·피해 숫자가 계속 덮는다). 세 겹으로 늘렸다: ⓐ 발밑 칩 10 → 13px ⓑ HUD 칩에 **이름**을 넣고(☠ 중독 6 · 2R) 숨쉬는 테두리 ⓒ **몸빛**(`--aura`)과 발밑 색 고리 + **HP 바 사선 줄무늬**.
- ⚠ **머리 위로 올리지 않았다.** 판이 302px뿐이라 윗줄(row 0)에 선 파이터의 머리 위는 이미 화면 밖이다(`.board`가 `overflow: hidden`). 그래서 가려질 수 없는 **몸빛 자체**를 바꿨다.
- ⚠ **HP 바의 채움 색은 갈아치우지 않는다** — 저체력 빨강이 그대로 살아 있어야 하므로 위에 줄무늬 한 겹(`.bhud__hphaze`)만 덮는다.
- ⚠ **몸빛 고리는 실제 DOM 노드**(`.fighter__aura`)다. `.fighter`의 `::before`는 접지 그림자, `::after`는 "나" 표식이 이미 쓰고 있어서 의사요소가 남아 있지 않다.

#### AI (`src/battle/ai.ts`)
2D·쿨타임 인식 그리디 3장 플랜: ⓪**위기 가드**(HP≤45면 첫 슬롯에 확률적으로 가드 — `panicGuard`, 2026-07-15) → ①**붕괴 이탈**(지금/다음 턴에 무너지는 열이면 공격보다 우선해 중앙 열로 이동. ⚠ **판 전체가 무너진 뒤에는 발동하지 않는다** — 갈 곳이 없는데 계속 걷기만 했다) → ②사거리에 들면 공격(난이도별 `aggression`) → ②′**회복**(2026-07-30) → ③기력 낮으면 원기 → ④상대와 행·열 정렬(접근/대시) → ⑤가끔 가드 → ⑥폴백. 쿨타임/잠금을 존중하며 슬롯마다 자기 위치·기력을 시뮬레이션.
- **②′ 회복(2026-07-30)**: 덱에 힐 카드가 있고 체력이 `char.maxHp`의 55% 이하이며 (힐 비용 + 최저가 공격)만큼 기력이 남을 때 힐을 낸다. 그전까지 AI는 `kind:'heal'`을 **한 번도 고르지 않아** `c-repair`가 든 덱(로그라이크 보상 풀·주술사)을 제대로 굴리지 못했다. 1:1 페이싱 영향은 미미(hard 6000판 평균 5.62→5.84턴, 중앙값 5 유지).
- **한계(알려진 것) 1 — 회피가 없다**: 상대의 사거리를 보고 **줄을 바꿔 피하는 로직이 없다**. 같은 줄을 훑는 원거리 카드(노바 블래스트·이온 랜스)에 특히 약해서, AI를 플레이어 대역으로 쓰는 시뮬(`npm run sim:run`)의 절대 수치는 사람보다 비관적으로 나온다 — 추세 비교용으로 읽어야 한다.
- **한계(알려진 것) 2 — 기력 문턱 인공물**: ③ 원기 회복 판단이 ④ 접근보다 먼저 와서, 기력이 `energyFloor`(hard 30) 바로 아래면 접근 대신 회복에 슬롯을 낭비한다. 그래서 "턴당 기력"이 그 문턱에 걸치는 캐릭터의 강도가 계단처럼 튄다(로그라이크 시뮬에서 VOLT 턴당 기력 8 vs 10이 클리어율 30% vs 50%). ③④를 맞바꿔 보니 1:1 밸런스가 무너져(VOLT 46%→67%, 평균 5.8→6.1턴) 되돌렸다 — 지금 순서가 캐릭터 간 기력 격차를 눌러주고 있다. **밸런스를 `turnEnergy`로 조정하지 말 것**(연속적인 훅으로 조정). 근본 해결은 AI의 자원 판단 개선.

## ⑤-bis 온라인 멀티플레이 (P2P + 짧은 코드) — 2026-06-18 추가 / 갱신

> 친구와 1:1 온라인 대전. **게임 데이터는 항상 P2P(WebRTC 데이터 채널)** 로 직접 흐른다. 연결 성사(시그널링)에만 약간의 중개가 필요하며, 두 가지 방식이 전송 추상화(`NetTransport`) 위에 올라간다:
> - **빠른 대전 — 랜덤 매칭(2026-07-15 추가 · ⚠ 2026-08-04 UI 중단)** — 사용자 결정으로 **버튼을 내렸다**. PVP는 **방 만들기 · 방 찾기** 두 경로로만 간다. 코드는 아래 그대로 살아 있고 `MultiplayerLobby`의 **`QUICK_MATCH_ENABLED`** 한 줄만 true로 되돌리면 버튼·대기 화면이 복원된다(되살릴 땐 RTDB 대기열 규칙과 `rules` 필터가 아직 열려 있는지 함께 확인). 구현: `src/net/matchmaking.ts`. RTDB 대기열 `gridbrawl-mm`에서: ①살아있는(심장박동 45초 이내) 대기표를 오래된 순으로 **ETag CAS**(`lock` 필드, REST `X-Firebase-ETag`/`if-match`)로 원자 선점 → 게스트로 answer 작성. ②없으면 내 대기표(offer + `createdAt`/`aliveAt` 서버시각)를 걸고 answer 폴링(호스트), 20초마다 심장박동. 대기 중에도 4초마다 재스캔해 **나보다 엄격히 먼저 온**(createdAt, 동률이면 id) 대기표가 보이면 그쪽 게스트로 전환 — 둘이 동시에 큐를 눌러 서로 기다리는 교착을 풀고, 엄격한 나이순이라 서로를 동시에 잡는 역교착은 불가능. 연결 시도 12초 타임아웃 후 다음 후보, 5분 지난 대기표는 스캔 중 청소. RTDB 규칙은 `gridbrawl-mm`에 offer/answer/createdAt/aliveAt/lock만 허용.
> - **짧은 6자리 룸 코드** — Firebase Realtime Database를 *시그널링*으로만 사용(SDP 교환). 사용자가 "AD3EF1"처럼 짧은 코드를 원해 도입(2차 결정). 6자리 코드는 정보량상 *반드시* 중개소의 열쇠여야 하므로(연결정보=DTLS 지문+ICE+IP 등) 시그널링 서버 없이는 불가능.
> - **(폴백) 복붙 초대 코드** — 백엔드 0, 전체 SDP를 base64 코드로 직접 주고받음. `net/webrtc.ts`의 `createHost`/`joinAsGuest`로 구현돼 있으나 현재 로비 UI는 짧은 코드만 노출(오프라인/무설정 폴백용으로 코드 보존).
>
> 핵심 설계 의도: **전송 계층을 게임에서 분리**(`src/net/protocol.ts`의 `NetTransport`) → 시그널링 방식을 바꿔도(서버/WebSocket/매치메이킹) 전투·UI 불변.

### 화면 흐름
`title → deck-select(캐릭터·덱 선택) → mode-select → mp-lobby(방 만들기 / 방 찾기 — 6자 코드) → mp-fight(전투) → mp-result(승/패)`. 타이틀의 **PVP** 버튼으로 진입. (`src/App.tsx`)

### 설정 (온라인 사용 전 필수)
- `.env`에 `VITE_FIREBASE_DB_URL=<RTDB URL>` 지정(미설정 시 로비가 "설정 필요" 안내를 띄우고 온라인 비활성). Firebase RTDB 규칙에서 `gridbrawl` 경로 읽기/쓰기 허용. 자세한 절차는 `.env.example`.
- 시그널링 데이터는 작고 1회성이며 **연결되면 자동 삭제**. SDK 없이 **REST + 폴링**으로 구현(`net/firebase.ts`).

### 연결 핸드셰이크 (짧은 코드, Firebase 시그널링)
1. **호스트**: `방 만들기` → `createOffer()`(ICE 수집) → 6자 코드 생성, RTDB `gridbrawl/<코드>/offer`에 SDP 기록 → `answer` 폴링.
2. **게스트**: `참가하기` → 코드 입력 → `offer` 읽기 → `createAnswer()` → `gridbrawl/<코드>/answer`에 기록.
3. **호스트**: `answer` 수신 → `acceptAnswer()` → 데이터 채널 오픈, 방 삭제. 양쪽 `NetTransport` 획득.
- STUN(`stun.l.google.com:19302`) 사용 → 대부분 NAT 통과. **대칭 NAT는 TURN 릴레이 필요**(아직 없음, 추후 업그레이드). 같은 LAN/PC는 STUN 없이도 동작.
- 연결 직후 양측이 `hello{charId, rules}`를 교환해 서로의 아바타와 **룰셋 버전**을 알아낸다.

### 룰셋 버전 게이트 (2026-08-05)
락스텝은 "두 피어가 같은 룰 코드를 돌린다"는 전제 위에 서 있는데, **웹은 배포 즉시 갱신되고 앱(스토어·OTA)은 늦게 따라오므로 버전이 겹치는 기간이 실제로 존재한다.** 카드 수치 한 줄만 달라도 두 화면이 조용히 갈린다 — 크래시가 아니라 desync라 재현이 거의 불가능하다. 그래서 붙기 전에 막는다.

- 기준값은 `battle/types.ts`의 **`RULES_VERSION`**. `resolveTurn`의 출력에 닿는 변경(룰 상수·엔진·카드 수치/사거리/능력·카드 id 추가삭제)을 하면 **같은 커밋에서 올린다**. 연출·UI·밸런스 시뮬만 바뀌면 올리지 않는다.
- **두 겹으로 막는다**:
  1. **빠른 대전** — 대기표(`gridbrawl-mm/<id>`)에 `rules`를 싣고, 스캔에서 값이 다른 대기표는 아예 후보에서 뺀다(`net/matchmaking.ts`). 헛되이 P2P를 맺지 않는다. ⚠ RTDB 규칙이 `$other: false`라 **`database.rules.json`에 `rules` 필드를 같이 열어야 한다** — 안 그러면 대기표 등록 자체가 거부된다.
  2. **핸드셰이크** — 방 코드 경로엔 대기열이 없으므로 `hello`에서 판정한다(`MultiplayerLobby.finishHandshake`). 다르면 전송을 닫고 "앱을 최신으로 업데이트하세요"로 로비 복귀.
- 양쪽이 서로에게 `hello`를 보내므로 판정도 양쪽에서 대칭으로 난다. 구버전 피어는 `rules`를 안 보내므로 `undefined ≠ RULES_VERSION`으로 자연히 걸린다.
- ⚠ **이 게이트는 온라인 매칭에만 건다.** 앱 진입이나 로그라이크를 막으면 오프라인에서 게임이 죽고, 그게 iOS 심사 2.1/4.2 반려 사유가 된다.

### 동기화 모델 — **결정론적 락스텝** (서버 없이 일치 보장)
- **핵심 전제**: `engine.resolveTurn(planA, planB)`은 **랜덤이 전혀 없는 결정론** 함수다(PvP엔 AI 미관여). 따라서 두 피어가 **동일 엔진**을 돌리고 매 턴 **카드 3장 ID만 교환**하면, 둘 다 같은 `resolveTurn`을 호출해 동일한 결과·애니메이션·상태에 도달한다.
- **정규 좌표(canonical) — 엔진 한정**: 엔진 상태는 양쪽 피어 모두 **호스트 = side 0(col 0 끝), 게스트 = side 1(col 5 끝)** 로 동일하게 구성. 이동 방향이 절대좌표(col +/-)이므로 엔진은 절대 미러링하지 않는다.
- 매 턴: 로컬 플레이어가 3장 확정 → `plan{turn, cards}` 전송 → 상대 plan 수신 → **양쪽 모두** `resolveTurn(side0Plan, side1Plan)` → 동일 진행. plan은 `turn` 번호로 태깅(순서 보장 채널이지만 버퍼링으로 위상차 흡수).
- **렌더링은 로컬 시점(2026-06-27)**: 각 피어는 **자기 캐릭터를 항상 왼쪽(오른쪽 바라봄)·상대를 오른쪽**에 본다. 엔진은 정규 좌표 그대로 두고 `BattleScreen`이 `localSide === 1`일 때만 화면 col을 좌우 반전(`flip`, `dcol = 5 - col`)해 렌더. 절대좌표 이동 카드가 깨지는 문제는, 반전 시 좌↔우 이동 카드의 **표시 라벨·화살표만 교체**(`faceCard`, id·엔진 입력은 정규 그대로)해서 "화살표 방향 = 화면에서 실제 가는 방향"을 보장하여 해결. 공격 카드 사정거리/예측 범위는 로컬이 항상 오른쪽을 보므로 "앞 = 오른쪽" 고정(미러 불필요). HUD도 자기 쪽을 왼쪽에 두고 **"나"** 배지. 각 피어는 자기 쪽(`localSide`)만 조작.
- 상대 연결 끊김: 대기 중 `getOpponentPlan`이 `null` 반환 → "상대 연결 끊김" 배너 후 메뉴 복귀.
- **턴 제한 30초(2026-07-17)**: 상대를 무한정 기다리는 루즈함을 없애는 장치. `BattleScreen`의 `turnSeconds` prop(온라인만 전달, 싱글·튜토리얼은 미지정)으로 카운트다운이 돌고(HUD `.bhud__timer`, 5초 이하 빨간 점멸), 0이 되면 **자동 제출**한다. 자동 제출 플랜은 항상 유효하게 만든다 — ①현재 3장이 완성·지불 가능하면 그대로 ②아니면 빈 슬롯을 **원기 회복**으로 메우고 ③그래도 기력이 모자라면 원기 회복 3장(비용 0·쿨0이라 언제나 유효). 각 피어가 **자기 플랜만** 자동 생성해 평소처럼 전송하므로 락스텝 결정론은 그대로(플랜을 주고받지, 재계산하지 않음). 수동/자동 이중 제출은 `submittingRef`로 차단.

## ⑥ 용어집
- **턴(Turn)**: **양측이 카드를 한 장씩 내는 것.** 코드에서는 슬롯(`slot`) — 한 라운드에 0·1·2 세 번 돈다. (2026-08-07 사용자 확정)
- **라운드(Round)**: **카드 3장을 고르고 그 3장을 다 쓰는 것 = 3턴.** `BattleState.round`가 세고 `CardBattle.resolveRound`가 한 번에 처리한다. 쿨타임·상태이상 지속·전장 붕괴가 전부 이 단위다.
- **페이즈(Phase)**: 한 턴(슬롯)의 해소 단계 — `move`(이동) → `defense`(수비) → `attack`(공격).
- **셀(Cell)**: 격자 칸 `{ col, row }`. 파이터의 위치 단위.
- **오프셋(Offset)**: 공격 `range`의 한 칸 `{ df, du }` — `df`=앞쪽(+상대 방향), `du`=위쪽(+위). `facing`으로 좌우 반전되어 실제 셀로 변환.
- **facing**: 바라보는 방향. p0=+1(오른쪽), p1=−1(왼쪽).
- **실드(shield)**: 가드로 쌓는 **라운드** 단위 피해 흡수 풀(라운드 시작에 지워진다). 중독·화상·독안개·관통은 이걸 그냥 지나간다.
- **쿨타임(cooldown)**: 카드 사용 후 잠기는 **라운드** 수. `state.cooldowns[p][id]`로 추적, 선택 시 0이어야 사용 가능.
- **스텝(Step)**: `resolveRound`가 반환하는 개별 해소 결과(애니메이션 1컷). 행동자·결과·데미지·스냅샷 포함.
- **건틀릿(Gauntlet)**: 나머지 파이터를 차례로 모두 상대하는 토너먼트 구조.
- **시그니처(signature)**: 캐릭터의 대표 강공격(코드의 `signature: true`).
- **지형(바위)**: 못 들어가고(이동·넉백이 앞에서 멈춤), 같은 줄/열이면 사격선을 끊고, 체력이 있어 부술 수 있다. **관통은 무시하고 뚫는다.** 밀어낼 곳이 막혀 한 칸도 못 밀리면 **그 라운드 기절**(2026-08-07부터 **벽도 포함**). 배치는 **그 몬스터가 데려온다**(엘리트·골렘·가디언·화염군주 — 일반 전투는 빈 판, 2026-08-07). 카드로도 세운다 — 수호기사의 「석벽 소환」과 **전사·마법사의 지형 카드**(앞 1·2칸, 상대가 있으면 밀어내고 기절)로 **PvP 판에도 놓인다**.
- **전장 붕괴(Collapse)**: 6**라운드**부터 양 끝 열(col 0·5)이 무너지기 시작해 3라운드마다 안쪽으로 번져 12라운드에 판 전체를 덮는 지속 피해 구역(단계별 라운드당 5 / 8 / 12). **들어갈 수는 있고 아플 뿐이다.** 무한전 종결 보장. (2026-08-05 이전 이름은 "독안개".)

## ⑥ 덱 빌딩 (2026-07-22 · 1단계 MVP)

전투 전에 자기 덱을 짜서 캐릭터·플레이어마다 다른 구성으로 싸운다. 구현은 `src/game/decks.ts`.

### 카드 분류
- **고정(7장)**: 이동 `m-up/m-down/m-right/m-left`(1칸), 지원 `c-brace`(기본 방어)·`c-energy`(원기) + **그 직업의 기본 공격 `basics[0]`**. ⚠ 일곱 번째가 캐릭터마다 다르므로 상수가 아니라 함수다(`fixedCardsFor(charId)`) — 2026-08-04 전에는 공용 `c-strike`로 고정이었다.
- **선택 풀(직업별, 이 중 7장)**: 이동 `m-right2`/`m-left2`(대시)·대각 4종, 공격 `c-shot` + **그 직업의 나머지 기본기 2장** + 그 직업 고유 공격, 지원 `c-guard`(더 좋은 방어)·`c-repair`(힐) + 고유 지원(전사 `war-wall`). ⚠ 직업마다 고유 카드 수가 다르다(전사 5·궁수 4·마법사 4).
- 전투 덱 = 고정 7 + 고른 7 = **14장**. 모든 덱 카드는 `deckFor(char)`(공용+기본기+고유)의 부분집합이므로 **멀티 락스텝의 상대 플랜 복원(`net/session.ts`)은 수정 없이 동작**한다.

### 저장·조립
- `Deck { id, name, charId, cardIds[7] }`. 로컬 저장은 `src/game/decks.ts`(localStorage), **계정 동기화는 `src/game/deckSync.ts`**.
- **계정별 저장(2026-07-23)** — 구글 로그인 사용자는 RTDB `decks/<uid>`가 원본(source of truth)이고 localStorage `gb-decks:<uid>`는 오프라인 캐시. 게스트/DB 미설정은 `gb-decks` 로컬 전용.
  - UI는 `deckSync`의 `listDecks()/putDeck()/removeDeck()`만 쓴다(비동기). 읽기 실패 시 캐시로 폴백해 오프라인에서도 플레이 가능, 쓰기는 **로컬 먼저 → 클라우드 업로드** 순.
  - RTDB는 `net/firebase.ts`와 같이 **REST 전용**, 권한은 Auth ID 토큰(`?auth=`, `net/auth.ts`의 `getIdToken()`). 규칙은 `database.rules.json`의 `decks/$uid`(본인만 읽기/쓰기 + 필드 검증) → 규칙 변경 시 `--only database` 배포 필수.
  - 로그인 직후 1회, 게스트 시절 로컬 덱을 계정으로 올린다(`gb-decks-migrated:<uid>` 플래그).
- `assembleDeck(deck)` = `fixedCardsFor(deck.charId)` + 고른 카드 → `BattleScreen`의 `deck` prop(로컬 손패).
- `PRESET_DECKS`(직업별로 손으로 고른 7장) = 봇 상대 덱 + 저장된 덱이 없을 때의 기본 덱.

### 화면·흐름
- `title →(게임 시작)→ run-start …`(로그라이크 — 2026-08-04부터 타이틀의 **게임 시작**이 곧 로그라이크다) | `title →(PVP)→ deck-select → mode-select →` 봇전 `fight → result` | 온라인 `mp-lobby → mp-fight → mp-result`.
- `deck-select →(덱 만들기)→ deck-manage`(목록·수정·삭제) `→ deck-build`(캐릭터 선택 + 풀에서 7장 토글 + 이름 저장). ⚠ 2026-08-04부터 **타이틀에는 덱 만들기가 없다** — 덱은 PVP에서만 쓰므로 PVP 안(덱 선택 화면 헤더)으로 옮겼고, `deck-manage`의 뒤로도 `deck-select`로 간다.
- **봇전은 1:1 단판** — 상대는 나와 다른 캐릭터를 랜덤으로 뽑고 그 캐릭터의 프리셋 덱을 쓴다(`decideAI`의 `availableCards` 인자).
