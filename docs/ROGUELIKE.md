# GridBrawl 로그라이크 모드 — 기획서 (2026-07-24)

> 단판 반복의 지루함을 해결하기 위한 **런(run) 기반 로그라이크**. 이 문서는 사용자 요구 + Claude의 검토·제안 + 구현 단계를 정리한다. 전투 룰 자체는 [GAME_DESIGN.md](GAME_DESIGN.md)가 진실 공급원이고, 이 문서는 그 위에 얹는 **메타 루프**를 다룬다.

---

## ① 왜 만드는가
지금은 봇전이 1:1 단판이라 이기든 지든 메뉴로 돌아온다 — **판 사이에 쌓이는 게 없어** 몇 판이면 최적 무브가 손에 익고 질린다. 로그라이크는 한 판을 "런의 한 걸음"으로 바꿔서, 덱·유물이 자라고 매 런이 달라지게 만든다.

---

## ② 핵심 루프
```
캐릭터 + 시작 클래스 카드 선택
  → 사다리(층) 전투: 약한 적 → 점점 강해짐
    → 승리 보상: [카드 3 · 유물 1 · 이벤트 1] 중 1택  또는  안 뽑고 HP 회복
    → (덱/유물 성장)
  → 엘리트 → 보스
  → 클리어 또는 사망(HP 0) → 결과
```
HP는 **판 사이에 이어진다**(전투 시작마다 풀피 아님) → 깔끔하게 이길수록 유리. 죽으면 런 종료.

---

## ③ 시작 조건 (사용자 정의)
- **시작 덱**(최소): 이동 4방향(상·하·좌·우) + 공용 공격 3장(스트라이크·펄스샷·잽) + 수비(브레이스·원기) + **직업 카드 1장(시작 시 선택)**.
- **시그니처 유물 1개**: 캐릭터 고유. **기존 패시브를 유물로 이관**한다(사용자 제안 채택). 예: VOLT는 "오버차지 코어"(매턴 기력·보호막), EMBER는 "불사조 깃털"(1회 부활).
- 나머지 직업 카드 3장·강한 공용 카드·유물은 **런 도중 보상으로 획득**.

---

## ④ 유물(Relic) 시스템
- **정의**: 상시 발동하는 능력 묶음 = 엔진 패시브 훅의 조합. 캐릭터의 옛 `passive`가 곧 유물 1개가 된다.
- **장착 = 효과 누적**: 여러 유물을 끼면 효과가 합산(merge)된다. 부활 유물 2개 = 2번 부활처럼 스택도 가능.
- **엔진 연동**: `CardBattle`가 그 전투의 **실효 패시브**를 `merge(장착 유물들)`로 계산한다. 멀티(PvP)는 1:1 그대로라 무관 — 런은 싱글 전용.
- **훅 목록**(엔진이 이해하는 능력, 결정론·락스텝 안전):
  | 필드 | 효과 | 예시 유물 |
  |---|---|---|
  | `turnEnergy` / `turnShield` | 매 턴 기력·보호막 +N | 오버차지 코어, 상시 방벽 |
  | `damageReduction` | 받는 피해 -N | 장갑판 |
  | `lifesteal` | 피해 준 만큼(고정 N) 체력 회복 | **송곳니(뱀파이어)** |
  | `revive` | 전투당 1회 HP N으로 부활(스택 가능) | **깃털(불사조)** |
  | `shieldBreak` | 적중 시 상대 보호막 제거 | 파쇄 날 |
  | `thorns`(신규) | 맞으면 공격자에게 N 반사 | 가시 갑옷 |
  | `regen`(신규) | 매 턴 체력 +N | 재생 나노봇 |
  | `attackBonus`(신규) | 내 공격 피해 +N | 분노의 인장 |
  | `maxHpBonus`(신규) | 최대 체력 ±N | 심장 강화, 광폭화 회로(-) |

## ⑤ 노드 사다리 · 보상 · 경제 (2026-07-24 개편)
런은 **노드 사다리**(기본 12층)다. 각 층은 타입이 있다: `combat`(일반 전투) · `elite` · `boss` · `event` · `shop`. 기본 배치는 전투 위주에 이벤트·상점을 섞고, 엘리트 뒤 보스(`NODE_TEMPLATE`).

**유물 획득 경로(확정)** — 사용자 요구 반영:
- 승리 보상은 **5장 중 1택** + **안 뽑고 HP 회복**(+22).
- **일반 전투**: 5장은 카드지만 **아주 낮은 확률(3%)로 그중 1장이 유물**로 바뀐다. (5장 중 1택이니 실질 유물 획득은 3% × 1/5 수준 — 사용자 계산 반영, `RELIC_IN_REWARD`.)
- **엘리트·보스**: 5장 중 1장이 **유물(확정)**.
- **이벤트**: 대가를 치르고 유물(HP 소모·카드 제거 등). ⑥ 참고.
- **상점**: 골드로 유물·카드·회복·카드 제거 구매. ⑦ 참고.

**골드 경제**: 전투 승리마다 골드 획득(층 스케일 + 엘리트·보스 보너스). 상점에서 소비.

**덱 상한 20**: 꽉 차면 카드 획득 시 **버릴 카드 1장 선택**(교체).

## ⑤-bis 이벤트 · 상점 (2026-07-24)
**이벤트**(`EVENTS`, 8종+): 각자 선택지가 있고 대부분 **위험-보상 거래**다. 사용자 요구대로 "HP 깎고 유물", "카드 빼고 유물"이 핵심.
- 저주받은 제단(HP-25→유물) · 버려진 대장간(카드 제거→유물) · 치유의 샘(HP+45) · 도박꾼(HP-15→골드) · 고대 사당(골드→HP) · 수상한 상자(HP-10→유물) · 흩어진 동전(골드) · 피의 서약(HP-20→골드).
- `resolveEventEffect(run, effect, removeCardId?)`가 적용. 카드 제거형은 카드 선택이 필요(`needsCardPick`).

**상점**(`rollShop`): 카드 3 + 유물 2 + 회복 1 + **카드 제거 서비스** 1. `buyShopItem`이 골드 검사·구매. 유물 가격은 희귀도별(common 60 / rare 90 / epic 130).

## ⑥ 난이도 곡선
- 층이 오를수록 적 **티어 상승** + HP/공격 **스케일 배수** 증가. **1층은 매우 약하게**(사용자 요구).
- 일정 층마다 **엘리트**(강화 몬스터 + 유물 확정), 마지막에 **보스**.

## ⑦ 몬스터 아이덴티티
각 몬스터는 **덱 + 패시브(유물) + AI 성격 + 기믹 카드**로 개성을 낸다. 아래는 1:1로 표현 가능한 설계:

| 몬스터 | 정체성 | 구현 |
|---|---|---|
| **슬라임** | 분열 | `revive`로 KO 시 작은 슬라임으로 되살아남 + 저댐 확산 공격 |
| **센트리(터렛)** | 원거리 견제 + 가끔 방어 | 장거리 빔 덱 + 가드, AI가 카이팅(접근 회피) |
| **오우거(브루저)** | 느리지만 한 방이 무겁다 | 고HP·고댐·넉백, 저빈도 |
| **버서커** | 저HP 유리대포 | 반동 고화력, 빨리 죽이거나 죽거나 |
| **뱀파이어** | 흡혈 지속 | `lifesteal` 유물 + 근접 |
| **가디언(벽)** | 방벽 세우고 한 방 | 높은 `damageReduction`·`turnShield` + 강한 시그니처 |
| **팬텀** | 회피·교란 | 십자/대각 공격 + 이동 잦음 |
| **보스: 오버로드** | 복합 | 고HP + 유물 다수 + 광역기 |

> **제안 / 중요한 스코프 결정 — "동시에 2~3명" 전투는 Phase 2**
> 사용자가 예로 든 "시작할 때 두세 명(원거리 담당 + 방어 담당)"은 **진짜 다인 전투**라, 엔진의 `pos/hp/chars`가 지금 **엄격히 1:1**(side0 vs side1)이라 코어를 N-인으로 재작성해야 한다(타겟팅·다중 HUD·다중 AI·렌더). 이건 큰 작업이고 멀티와 무관(싱글 전용)하다. 그래서:
> - **Phase 1(지금)**: 1:1 유지. "분열·벽·원거리+방어" 같은 개성은 **덱/패시브/AI/기믹 카드**로 낸다(위 표). 슬라임 분열은 부활로 "쪼개지는 느낌"을 준다.
> - **Phase 2(추후)**: 엔진을 다인(2~3)으로 일반화해 진짜 다인 전투 도입.

## ⑧ 구현 단계
- **Phase 1a — 데이터·엔진 토대** *(완료·검증)*: 유물 42종(`game/relics.ts`) + 패시브 훅 확장(엔진) + 몬스터 20종(`game/monsters.ts`) + 노드 사다리·이벤트·상점·골드(`game/run.ts`). 순수 로직, 타입검사 + 시뮬 검증.
- **Phase 1b — UI·흐름** *(완료·플레이 검증)*: `RunStartScreen`(캐릭터+클래스 카드) · `RunMapScreen`(12노드 사다리+런 바) · `RewardScreen`(5중1·HP회복·덱꽉참 교체) · `EventScreen`(선택지·카드제거) · `ShopScreen`(골드 구매) · `RunEndScreen`. `App.tsx`에 `run-*` 페이즈 연결. `BattleScreen`에 `battleOpts`(유물 merge·몬스터 스탯) + 실효 최대체력 HUD. 브라우저에서 1→5층(전투·보상·이벤트·상점) 검증.
- **Phase 1c — 콘텐츠·밸런스**: 유물·몬스터 대량 추가, 이벤트, 난이도 곡선 튜닝, `npm run sim` 확장.
- **Phase 2 — 다인 전투** *(추후, 큰 작업)*: 엔진 N-인 일반화.

---

## ⑨ Claude의 검토 요약(이상한 점·제안)
1. **다인 전투는 스코프가 크다 → Phase 2로 분리**. Phase 1은 1:1로 개성을 낸다.
2. **매판 유물은 과다** → 일반은 저확률, 엘리트·보스는 확정(상수로 조정).
3. **덱 상한 필요** → 꽉 차면 교체.
4. **패시브→유물 이관은 좋은 설계** → 시그니처 유물로 채택, 모든 상시 능력의 단일 홈이 된다.
5. HP 판간 인계 + 죽으면 런 종료로 **한 판 한 판에 무게**를 준다(원작의 사다리 긴장감).
