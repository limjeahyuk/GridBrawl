# GridBrawl 로그라이크 모드 — 기획서 (2026-07-24)

> 단판 반복의 지루함을 해결하기 위한 **런(run) 기반 로그라이크**. 이 문서는 사용자 요구 + Claude의 검토·제안 + 구현 단계를 정리한다. 전투 룰 자체는 [GAME_DESIGN.md](GAME_DESIGN.md)가 진실 공급원이고, 이 문서는 그 위에 얹는 **메타 루프**를 다룬다.

---

## ① 왜 만드는가
지금은 봇전이 1:1 단판이라 이기든 지든 메뉴로 돌아온다 — **판 사이에 쌓이는 게 없어** 몇 판이면 최적 무브가 손에 익고 질린다. 로그라이크는 한 판을 "런의 한 걸음"으로 바꿔서, 덱·유물이 자라고 매 런이 달라지게 만든다.

---

## ② 핵심 루프
```
캐릭터 선택 (시작 덱 = 기본 카드 9장 — 공용 6 + 직업 기본기 3)
  → 사다리(15층) 전투: 약한 적 → 점점 강해짐
    → 승리 보상: 6장 중 1택(직업 카드·런 전용 카드·유물)  또는  안 뽑고 HP 회복
    → (덱/유물 성장)
  → 엘리트 → 보스
  → 클리어 또는 사망(HP 0) → 결과
```
HP는 **판 사이에 이어진다**(전투 시작마다 풀피 아님) → 깔끔하게 이길수록 유리. 죽으면 런 종료.

> **구현 주의(2026-07-30)**: 이 HP 이월은 Phase 1b까지 *반쪽*이었다 — `afterWin(run, hpLeft)`가 남은 체력을 런 상태에 기록해 지도·HUD엔 보였지만, `CardBattle`은 늘 `maxHp`로 시작해 **다음 전투는 풀피로** 시작했다. 이제 `BattleOpts.startHp`로 넘긴다(`runbattle.ts`: `startHp: [run.hp, undefined]` — 플레이어만 이월, 몬스터는 풀피). 런 난이도의 핵심 압박이 여기 걸려 있으니 이 배선을 끊으면 밸런스가 통째로 무의미해진다.

## ③ 시작 조건 (2026-07-31 개편 — 직업 카드는 번다 / 2026-08-04 기본기 직업화)
- **시작 덱 = 기본 카드 9장뿐**: 이동 4방향 + 버티기 + 원기(공용 6장) + **그 직업의 기본 공격 3장**(`CharacterDef.basics`, `startingDeck(charId)`). 캐릭터 선택만 하고 출발한다.
  - ⚠ 2026-08-04 전에는 이 3장이 **공용 약공**(내려치기·돌팔매·찌르기)이라 세 직업의 1~5층이 똑같은 싸움이었다. 총합 화력은 그대로 두고 **때리는 모양**만 갈랐다(전사=밀착·강타 / 궁수=긴 사거리 / 마법사=광역). 표·근거는 [GAME_DESIGN.md](GAME_DESIGN.md) ④ "직업 기본기".
- **시그니처 유물 1개**: 캐릭터 고유(기존 패시브를 이관, 런 수치는 ⑪).
- **직업 카드 4장 · 런 전용 카드 · 유물은 전부 보상으로 번다.** 직업 카드를 아직 못 얻었으면 승리 보상 한 칸이 **직업 카드로 보장**된다(못 주우면 런이 성립하지 않으므로).

> **왜 시작 직업 카드 선택을 없앴나** — 예전엔 고유 카드 4장 중 1장을 골라 시작했다. 런에선 큰 카드가 항상 유리해서(제약이 기력이 아니라 슬롯 3칸) "시그니처로 시작"이 유일한 정답이 되고 나머지 3장은 함정이었으며(클리어율 11% ↔ 40%), 그 시작이 1~6층을 통과율 98~100%의 무료 구간으로 만들었다. 사용자 결정으로 ⓑ안(보상으로 벌기)을 택했다 — 기획서 ③의 원래 의도이자, 이제 사다리 전체가 성장 곡선이 된다.

## ④ 유물(Relic) 시스템
- **정의**: 상시 발동하는 능력 묶음 = 엔진 패시브 훅의 조합. 캐릭터의 옛 `passive`가 곧 유물 1개가 된다.
- **장착 = 효과 누적**: 여러 유물을 끼면 효과가 합산(merge)된다. 부활 유물 2개 = 2번 부활처럼 스택도 가능.
- **엔진 연동**: `CardBattle`가 그 전투의 **실효 패시브**를 `merge(장착 유물들)`로 계산한다. 멀티(PvP)는 1:1 그대로라 무관 — 런은 싱글 전용.
- **훅 목록**(엔진이 이해하는 능력, 결정론·락스텝 안전):
  | 필드 | 효과 | 예시 유물 |
  |---|---|---|
  | `turnEnergy` / `turnShield` | 매 턴 기력·보호막 +N | 오버차지 코어, 상시 방벽 |
  | `damageReduction` | 받는 피해 -N | 장갑판 |
  | `lifesteal` | 피해 준 만큼(고정 N) 체력 회복 | **송곳니(뱀파이어)** |
  | `revive` | 전투당 1회 HP N으로 부활(스택 가능) | **깃털(불사조)** |
  | `shieldBreak` | 적중 시 상대 보호막 제거 | 파쇄 날 |
  | `thorns`(신규) | 맞으면 공격자에게 N 반사 | 가시 갑옷 |
  | `regen`(신규) | 매 턴 체력 +N | 치유의 이끼 |
  | `attackBonus`(신규) | 내 공격 피해 +N | 분노의 인장 |
  | `maxHpBonus`(신규) | 최대 체력 ±N | 심장 강화, 광기의 낙인(-) |
- **조합형 훅**(2026-07-31 추가 — 상세는 ⑫):
  | 필드 | 효과 | 예시 유물 |
  |---|---|---|
  | `energyTriggers[]` | 누적 기력 `per`마다 기절·회복·보호막·피해·기력 | 넘치는 술잔(200→기절), 순환의 매듭(100→회복) |
  | `lowHpBonusPct` | 체력 절반 이하일 때 내 공격 피해 +N%(합산) | 벼랑의 각오(+50%), 사경의 광기(+100%) |
  | `alwaysPierce` | 내 모든 공격이 보호막을 관통 | 공허의 날 |
  | `stunOnHit` / `stunCap` | 적중 시 기절(전투당 `stunCap`회) | 강타의 인장 |
  | `openingShield` | 첫 턴 보호막 +N | 선제 방벽 |
  | (전투 밖) `RunMods` | 상점 할인·골드·보상 칸·회복량·덱 상한 | 상인의 인증패, 두툼한 지갑, 점술 수정구 |

## ⑤ 노드 지도 · 보상 · 경제 (2026-07-24 개편 → 2026-07-30 15층 → 2026-08-04 분기)
런은 **15층 지도**다. 각 층은 타입이 있다: `combat`(일반 전투) · `elite` · `boss` · `event` · `shop`.

**층 골격(`NODE_TEMPLATE`)** — 전투 7 + 엘리트 2 + 보스 1 + 이벤트 3 + 상점 2:
```
1 전투 · 2 전투 · 3 이벤트 · 4 전투 · 5 상점 · 6 전투 · 7 엘리트
8 이벤트 · 9 전투 · 10 엘리트 · 11 상점 · 12 전투 · 13 전투 · 14 이벤트 · 15 보스
```
12층에서 늘린 이유(둘 다 시뮬 근거, ⑩ 참고):
- 전투가 8판뿐이라 **tier3 몬스터가 9층 한 칸에서만** 나왔다(팬텀·뱀파이어 조우 60회 vs 잡졸 600회) — 층을 늘려 각 티어에 제 몫의 자리를 줬다.
- 첫 엘리트가 5층이던 배치에선 체력 50%·유물 1개로 벽을 만나 **그 층이 보스보다 어려웠다**(통과 66% vs 보스 79%). 첫 엘리트를 7층으로 물리고 **그 앞에 상점(5층)**을 뒀다.

### ⑤-bis 분기 지도 → **사다리 그래프** (2026-08-04 → 2026-08-05 개편)

선형 사다리는 **고를 것이 없어서** 지도가 그냥 진행 표시줄이었다. 그래서 층마다 갈래를 뒀는데
(2026-08-04), 그것도 **층마다 독립된 2택**이라 무엇을 고르든 다음 층이 똑같이 열렸다 — 고른 게
뒤에 아무 영향이 없으니 지도가 아니라 팝업 두 개였다("2가지 중 하나를 고르는 느낌").

**지금은 칸끼리 간선으로 이어진 그래프다**(2026-08-05, `map`·`picked`·`chooseBranch`,
화면은 `RunMapScreen`). 규칙은 하나뿐이다 — **직전에 고른 칸에서 이어진 칸만 고를 수 있다.**
그래서 갈래가 **1~3개로 달라지고**, 앞쪽 상점을 노리려면 몇 층 전부터 그 줄을 타야 한다.

**생성 규칙(`buildMap`)**

| 요소 | 규칙 |
| --- | --- |
| 줄(lane) | 0·1·2 세 줄. **가운데(1)는 모든 층에 반드시 있다** |
| 층 폭 | 1(18%) / 2(50%) / 3(32%) — 1이 섞여야 길이 다시 모이는 "허리"가 생긴다. 1층은 2, 보스 층은 1 |
| 간선 | 세로로 **한 칸 안쪽**(\|Δlane\| ≤ 1)까지만. 갈 곳이 없으면 가장 가까운 칸으로 잇고, 들어오는 길이 없는 칸도 같은 식으로 이어 준다 |
| 칸 종류 | **가운데 줄에 템플릿 타입**을 놓고, 나머지 줄은 아래 대안 규칙 |

**대안 칸 규칙(`nodesForFloor`)**:

| 골격 | 갈래 | 무엇을 고르는가 |
| --- | --- | --- |
| 전투 | 전투 A / 전투 B(다른 몬스터) | 어느 적을 상대할지 |
| 엘리트 | 엘리트(가운데) / 일반 전투 | 유물 확정 ↔ 안전 |
| 이벤트 | 이벤트 / 상점 | 도박 ↔ 확실한 보급 |
| 상점 | 상점 / 이벤트 | 골드가 없으면 차라리 도박 |
| 보스 | (없음) | 마지막 층은 고를 게 없다 |

- ⚠ **가운데 줄만 밟는 경로가 곧 분기 이전의 선형 사다리다.** 어느 칸에서든 |Δlane| ≤ 1로
  가운데에 닿으므로 그 경로는 **항상 존재한다** — 시뮬로 맞춰 둔 밸런스 기준선이 지도 안에
  경로로 남아 있는 것이고, `--path=template`이 그 경로다(`templateOptionIndex`).
  ⚠ 그래프가 된 뒤로는 **"늘 0번"이 더 이상 옛 사다리가 아니다**(선택지 목록이 직전 칸에
  따라 달라진다). 생성 규칙을 바꾸더라도 "가운데 줄은 늘 있고 늘 이어져 있다"는 지킬 것.
- 불변식은 `npm run check`가 10건으로 지킨다 — 막다른 칸 없음 / 고아 칸 없음 / 간선은 한 줄까지 /
  어느 칸에서든 다음 층 가운데로 이동 가능 / 층 폭이 1~3으로 섞임 등.
- ⚠ **지원 칸(이벤트·상점)의 대안을 전투로 두면 안 된다.** 처음에 모든 대안을 전투로 뒀다가
  경로를 헤맬수록 이벤트·상점이 전투로 갈려 나가 **클리어율이 27% → 10%로 무너졌다**.
  상점이 층 사이 회복의 주 수단(`PRICE_HEAL_AMOUNT` 50)이라 그게 빠지면 회복이 끊긴다.
  지원 칸은 **서로하고만** 바꿔 전투/지원 비율을 경로와 무관하게 유지한다.
  `npm run check`의 "지원 칸은 전투로 바뀌지 않는다"가 이걸 지킨다.

**경로가 결과를 가른다**(900런 `--seed=12345`, `--path=`. 2026-08-05 그래프 지도 +
유물/카드 2배 + `mergeRelics` 수정 **이후** 값):

| 경로 | 클리어율 |
| --- | --- |
| `template` 가운데 줄(옛 사다리) | 31.0% |
| `random` 무작위(기본) | **28.8%** |
| `greedy` 엘리트 우선 | 28.3% |
| `safe` 엘리트 회피 | 26.9% |

**엘리트를 피하는 쪽이 여전히 손해다**(`safe` 26.9% ↔ `greedy` 28.3%) — "안전 경로가 최적"이
되면 분기 설계가 실패한 것인데, 그 함정은 피했다. 다만 그래프가 되면서 **차이가 줄었다**
(예전엔 7.1%p, 지금은 1.4%p): 엘리트를 고르려면 그 줄에 붙어 있어야 해서 `greedy`가 늘
엘리트를 먹지는 못하기 때문이다. 이 격차를 다시 벌리고 싶으면 엘리트 보상 쪽을 손볼 것.

⚠ **캐릭터 밴드는 기본 정책 `random` 기준으로 맞춰져 있다**(5시드 × 900런 평균
**0.9%p** · WARRIOR 29.7 / ARCHER 28.9 / MAGE 28.8 · 클리어율 29.1%). 극단 경로에서는
더 벌어질 수 있다 — 어느 경로를 기준으로 삼을지는 나중에 다시 정할 문제다.

**유물 획득 경로(확정)** — 사용자 요구 반영:
- 승리 보상은 **6장 중 1택** + **안 뽑고 HP 회복**(`SKIP_HEAL` 36). 카드 풀 = 공용 확장(대시·대각·방패 세우기·상처 봉합) + **그 직업의 고유 카드 8~9장** + **런 전용 카드 50장**(⑫).
- 직업 카드를 아직 못 얻었으면 **한 칸은 직업 카드로 보장**(2026-07-31).
- **일반 전투**: 낮은 확률(3%, 유물 `relicChanceBonus`로 상승)로 한 칸이 유물.
- **엘리트·보스**: 한 칸이 **유물(확정)**.
- 유물은 **희귀도 가중 + 깊이 보정**으로 뽑는다(⑫) — 얕은 층에선 전설이 거의 안 나온다.
- **이벤트**: 대가를 치르고 유물(HP 소모·카드 제거 등). ⑥ 참고.
- **상점**: 골드로 유물·카드·회복 구매. ⑦ 참고.

**골드 경제**: 전투 승리마다 골드 획득(층 스케일 + 엘리트·보스 보너스). 상점에서 소비. 런당 약 350골드가 들어온다.

**보상 포기 회복(`SKIP_HEAL`)**: 22 → 32 → **36**(2026-07-31). 15층 사다리의 누적 소모에선 22가 "카드를 포기할 이유"가 못 됐다.

### 카드 룰 (2026-08-05 확정)

**전제 — 덱이 곧 손패다.** 셔플도 드로우도 없고, 전투 손패는 덱 전체다(`BattleScreen`의 `hand = deck`). 그래서 **카드가 많을수록 무조건 유리하고, "덱 압축"은 이 게임에 존재하지 않는 전략이다.** 다른 로그라이크의 감각을 그대로 들여오면 안 된다.

| 규칙 | 값 | 근거 |
| --- | --- | --- |
| 덱 상한 | **20장**(`DECK_CAP`, 유물로 +2~4) | 많을수록 유리하므로 **상한이 유일한 선택 압박**이다. 꽉 찬 뒤의 보상은 "받을까"가 아니라 "무엇과 바꿀까"가 된다 |
| 줄이는 길 | **교체뿐** | 꽉 찬 채로 카드를 얻으면 1장을 버린다(`grantCard`의 `needsReplace`). 보상·상점 카드 구매가 그 자리 |
| 잠긴 카드 | **이동 4방향**(`LOCKED_CARD_IDS` = `m-up/m-down/m-left/m-right`) | 이동은 **판의 칸을 눌러서** 하고, 그 칸은 덱의 이동 카드로 만들어진다 — 한 장이 빠지면 그 방향이 영영 안 밝혀지고 **이유조차 안 보인다** |
| 유료 카드 제거 | **없앰**(옛 상점 서비스 40골드) | 얇게 만들 이득이 0이라 **사는 순간 손해인 함정 칸**이었다. 자리를 비우는 일은 교체가 공짜로 한다 |
| 카드 → 유물 거래 | **유지**(이벤트 "카드를 녹인다") | 이건 줄이는 게 아니라 **더 강한 것으로 바꾸는 것**이라 성립한다 |

- ⚠ 잠기는 건 **직교 이동 4장뿐**이다. 나중에 주운 대시·대각 이동(`m-right2`·`m-ur` 등)은 같은 `kind: 'move'`지만 잠기지 않는다 — 꽉 찬 덱에서 더 좋은 카드와 바꿀 길을 막으면 안 되기 때문이다. **`kind`가 아니라 목록으로 판정한다.**
- 막는 곳은 엔진 쪽 `removeCard`·`grantCard`·`resolveEventEffect` 셋 + UI의 `DeckPicker`(자물쇠 표시). ⚠ UI에서 잠긴 카드에 `disabled`를 걸지 않는다 — **꾹 눌러 읽을 수조차 없어진다**(왜 못 고르는지 가장 궁금한 카드가 바로 그 카드다).
- 검증 `npm run check` 9건(덱 룰 절).
- 밸런스: 상점 서비스 삭제는 **기준 스윕(greedy)에 영향 0**이다 — greedy 정책은 그 칸을 애초에 사지 않았고, `worstCard`도 이미 이동 4장을 남기고 있었다(이제 `isLockedCard`를 그대로 쓴다).

## ⑤-bis 이벤트 · 상점 (2026-07-24)
**이벤트**(`EVENTS`, 8종+): 각자 선택지가 있고 대부분 **위험-보상 거래**다. 사용자 요구대로 "HP 깎고 유물", "카드 빼고 유물"이 핵심.
- 저주받은 제단(HP-25→유물) · 버려진 대장간(카드 제거→유물) · 치유의 샘(HP+45) · 도박꾼(HP-15→골드) · 고대 사당(골드→HP) · 수상한 상자(HP-10→유물) · 흩어진 동전(골드) · 피의 서약(HP-20→골드).
- `resolveEventEffect(run, effect, removeCardId?)`가 적용. 카드 제거형은 카드 선택이 필요(`needsCardPick`). ⚠ 잠긴 카드(이동 4방향)를 고르면 대가를 안 치른 셈이라 **유물도 주지 않고 다시 고르게** 한다.

**상점**(`rollShop`): 카드 3 + **유물 1** + **회복 2**(각 30골드에 HP+50). `buyShopItem`이 골드 검사·구매. ⚠ **"카드 1장 제거"(40골드)는 2026-08-05에 뺐다** — 덱이 곧 손패라 얇게 만들 이득이 0이고, 꽉 찬 뒤 자리를 비우는 일은 카드 구매 시의 교체가 공짜로 해 준다. 즉 **어떤 상황에서도 사면 손해인 칸**이었다(위 "카드 룰"). 되살리지 말 것. 유물 가격은 희귀도별(`RELIC_PRICE` — 일반 60 / 희귀 95 / 영웅 145 / **전설 230**)이고, 상점 할인 유물이 **모든 가격**에 적용된다.
- 유물 2 → **1칸**(2026-07-30): 상점 2곳에서 유물 4개를 사들이면 후반이 무력화됐다. 유물의 주 경로는 엘리트·이벤트다.
- 회복 1 → **2칸**, 회복량 35 → **50**: 시뮬에서 보스 도달 시 **골드 276이 남았다**(살 게 없었다). 남는 골드가 생존으로 이어지는 창구를 넓혔다.

## ⑥ 난이도 곡선 (2026-07-30 튜닝 — 상수는 `game/run.ts`)
층이 오를수록 적 **티어 상승** + **체력·공격력 스케일** 증가. **1층은 매우 약하게**(사용자 요구). 일정 층마다 **엘리트**(강화 몬스터 + 유물 확정), 마지막에 **보스**.

| 상수 | 값 | 뜻 |
|---|---|---|
| `HP_SCALE_PER_FLOOR` | 0.07 | 층당 몬스터 최대 체력 +7% |
| `atkScaleAt(floor)` | `0.3d + 0.048d²` (d=층-1) | 층당 몬스터 **공격력**(4층 +1 · 7층 +3 · 10층 +7 · 13층 +11 · 15층 +14) |
| `ELITE_HP_MULT` / `ELITE_ATK_BONUS` | 1.2 / +2 | 엘리트 노드 보정(tier4는 이미 엘리트 스탯이라 **중복 적용 안 함**) |
| `BOSS_HP_SCALE_FACTOR` | 0.4 | 보스는 층 체력 스케일을 40%만 먹는다 |
| `combatTier` / `combatPool` | t1: 1~3층 · t2: 4~8층 · t3: 9층+ · **12층부터 tier4도 잡몹으로** | 일반 전투 후보 |
| `MID_ELITE_IDS` / `DEEP_ELITE_IDS` | 골렘·오우거·기사 / 수호기사·화염군주·가디언(9층+) | 엘리트 후보(깊이별) |

**왜 공격력 스케일이 선형이 아닌가** — 플레이어의 방어는 유물로 *합산*된다(피해감소 + 매 턴 보호막 + 재생 + 흡혈). 층당 고정 +N으로는 앞쪽 층이 아파지기 전에 뒤쪽 층을 뚫지 못한다. 실제로 체력만 스케일하던 버전에선 후반 몬스터가 "두껍지만 안 아픈" 샌드백이 되어 **12·13층 통과율이 99%**였고, 플레이어가 그 층에서 오히려 체력을 **벌어서** 나왔다. 그래서 초반은 완만하고 후반에 방어 스택을 넘어서는 2차 곡선을 쓴다.

**후반 몬스터 설계 원칙(위 결론의 따름 정리)**: 잔챙이 타격 여러 번보다 **한 방의 크기**가 중요하다. 보호막·피해감소는 타격마다 깎이므로, 25짜리 3방은 0이 되고 60짜리 1방은 들어간다. 후반 몬스터엔 `attackBonus`나 고화력 카드를 준다(뱀파이어·팬텀에 `attackBonus: 6`을 준 이유).

**보스는 두꺼워지는 대신 아파진다**: 층 스케일을 그대로 먹이면 15층 오버로드가 체력 400에 육박해 **15턴 독안개 소모전**이 됐고, 그 싸움은 지속력을 쌓은 플레이어가 그냥 이겼다(승률 79%). 체력 스케일을 깎고 화력 곡선에 맡겨 **11턴·승률 65%**의 짧고 무서운 싸움으로 조정했다.

## ⑦ 몬스터 아이덴티티
각 몬스터는 **덱 + 패시브(유물) + AI 성격 + 기믹 카드**로 개성을 낸다. 아래는 1:1로 표현 가능한 설계:

### ⑦-0 전투 변주 — 매 전투가 다르게 (2026-08-05)

20종이 단 하나의 `decideAI`를 공유해 **"멀면 붙고 닿으면 때린다"만 반복**했다. 슬라임·도끼병이 처음부터 똑같이 대시하고, 같은 몬스터는 판마다 개전이 판박이였다. 세 축으로 갈랐다 — 셋 다 **런(싱글) 전용**이라 PvP 락스텝(몬스터 없음)과 무관하고, 시뮬은 시드 RNG라 재현된다.

- **ⓐ 성격 `MonsterDef.behavior`(`ai.ts`의 `Archetype`·`ARCH`)** — 난이도 cfg(공격성·가드 성향·패닉 가드·기력 문턱)를 밀고 `keepGap`으로 접근/후퇴를 가른다:
  - `rusher`(도끼병·고블린·버서커·암살자) — 공격성↑ 가드↓, 무조건 파고든다
  - `kiter`(석궁병·감시안·마녀) — 상대와 가로 간격이 `keepGap`(2)보다 좁아지면 **물러나 같은 줄에서 원거리로 쏜다**(`kiteCards`). 벽에 몰리면 approach로 떨어져 최소한 줄이라도 맞춘다
  - `turtle`(기사·골렘·가디언·주술사·수호기사) — 가드를 자주 들고 상대가 오길 기다린다
  - `skirmisher`(박쥐·팬텀) — 줄을 옮겨 다니며 견제
  - `balanced`(슬라임·오우거·뱀파이어·분열체·보스류) — 조정 없음
- **ⓑ 랜덤 시작 위치 `BattleOpts.startCells`** — 4행 전환(2026-08-05) 뒤로 **양쪽 다** 자기 끝열의 네 칸(row 0~3) 중 무작위로 세워, 세로로 어긋난 채 개전한다(플레이어 col 0 / 몬스터 col 5). **보스만 양쪽 row 1 고정**(연출·스크립트가 자리를 전제). ⚠ 런 전용이다 — PvP는 `startCells`를 안 넘겨 고정 `START_CELLS`를 쓰므로 락스텝 안전. 시뮬은 `Math.random`을 시드로 갈아끼워 재현된다.
- **ⓒ 전투별 기분 `AIProfile.moodAgg`** — `runbattle.runFightProps`가 판 시작 때 한 번 `(rand−0.5)×0.24`(≈±0.12)를 굴려 그 판 내내 고정으로 `decideAI`에 넘긴다. 공격성 ±0.12·가드 ∓0.05를 흔들어 **같은 몬스터라도 판마다** 공격/가드 확률이 다르다(개전 이동은 결정론이라 안 바뀌고, 교전 중 확률 분기에서 나타난다).

⚠ **밸런스 영향** — 5시드 스윕에서 밴드 3.5→3.6%p로 유지(궁수만 +2.6%p: 카이터가 밀착사각을 덜 노출). `SIGNATURE.runEffect` 재조정 없이 성립했다. `ARCH` 수치나 `moodAgg` 폭을 건드리면 `sim:run --sweep`를 다시 돌린다.

## ⑦-bis 보스 스크립트 패턴 (2026-07-24)
보스는 일반 그리디 AI 대신 **턴 기반 정해진 리듬**으로 싸우고, **예고(telegraph)**로 플레이어가 막거나 피할 여지를 준다(`game/bosses.ts`). 결정론적(turn·hp만 사용) — 랜덤 없음.
- **지도 공개**: `RunMapScreen` 트랙이 층마다 **갈래를 세로로 쌓고**, 모든 칸에 **아이콘 + 이름**(몬스터 칸은 몬스터 이름)을 띄운다 — 15층 앞까지 뭐가 있는지 첫 화면부터 읽힌다. 이번 층 칸에는 **적 체력**(또는 칸 종류의 한 줄 요약)이 더 붙는다.
  - ⚠ **고르는 자리와 보는 자리를 하나로 합쳤다**(2026-08-04 2차). 처음엔 아래에 큰 선택 카드 2장을 따로 뒀는데, 카드가 화면 절반을 먹어 **지도가 얇은 띠로 눌려 앞이 안 보였다**("경로를 다르게 가야 하는데 너무 작다"). 이제 지도의 칸을 직접 누른다.
  - ⚠ **앞으로의 층은 숫자를 안 보여 준다** — 층 스케일이 그 층 기준이라 지금 계산하면 거짓말이 된다. 이름·종류까지만 미리 보여 주고, 체력은 그 층에 도착했을 때만.
  - ⚠ **가로가 유일한 제약**이다. 15층이 한 줄에 들어가야 경로가 왼→오로 읽힌다(`.runcol` 76px × 15 + gap = 1196 / 안폭 1220). 층을 늘리면 여기가 먼저 깨진다 — 줄바꿈은 경로 읽기를 망치므로 칸 너비부터 다시 계산할 것.

- **「불씨 모으기」가 이 개편의 핵심**이다. 예전엔 "힘을 모은다"가 예고 문구뿐이고 실제로는 아무것도 쌓이지 않았다. 이제 `empower`가 **이 전투 내내 남아서**, 오래 끌면 진짜로 더 아파진다 — 충전 턴이 곧 반격 창이라는 설계가 그제야 성립한다.
- ⚠ **충전 턴에는 정말 약해야 한다.** 처음엔 충전 턴에도 채찍·기둥을 같이 넣었는데, 그러면 매 턴 두 대씩 맞아서 "반격 창"이 거짓말이 된다 — 시뮬에서 화염군주 조우 승률이 **44%**까지 떨어져 혼자 벽이 됐다(수호기사 71 · 가디언 68). 충전 턴을 불씨 한 장으로 줄이고 인페르노 40→32 · 기둥 28→23으로 내려 **59%**에 맞췄다.
- ⚠ **보스 카드가 플레이어 풀에 새어 나가면 안 된다.** `deckFor`(덱 빌더)·`RUN_CARDS`(보상) 어느 쪽에도 없고, `monsters.ts`의 카드 해석기에서만 풀에 들어간다. `npm run check`가 지킨다.
- ⚠ **무대는 노드 종류가 아니라 몬스터 id로 고른다**(`sceneFor`). 수호기사·화염군주는 `boss` 칸이 아니라 **엘리트 칸**으로 나오므로, 종류로 판정하면 둘은 영영 자기 무대를 못 본다.
- **컷인 2종**(`BossCinematic` → `BattleScreen`의 `boss` prop): **등장**(전투 시작, 첫 카드를 고르기 전)과 **격노**(체력이 `enrageAt` 아래로 내려가는 순간, 스텝 사이를 끊고). 2.3초, 방사형 빛살 + 대형 초상 + 칭호·이름·태그라인. 필살기 컷인(`.cutin`)과 **일부러 다른 언어**를 쓴다 — 저쪽은 대각 스트리크가 옆으로 쓸고, 이쪽은 빛살이 가운데서 퍼진다. 같은 모양이면 등장 컷인이 "필살기가 또 나왔나"로 묻힌다.
  - ⚠ 격노 판정은 `battle.state`가 아니라 **그 스텝의 스냅샷**(`full.hp`)으로 한다. 엔진은 턴을 통째로 먼저 계산하고 스텝은 그 재생이라, `battle.state`를 보면 첫 스텝부터 이미 턴 끝 체력이라 컷인이 한 턴 일찍 튄다.
  - ⚠ `enrageAt`은 스크립트의 페이즈 전환 문턱과 **같아야** 한다(수호기사 0.35 · 나머지 0.4). 어긋나면 "컷인은 떴는데 행동은 그대로"가 된다. `npm run check`가 검사한다.
- **HUD·무대도 보스 색을 탄다**: 상대 쪽에 `BOSS` 칩 + 칭호 한 줄, HP 바에 **페이즈 전환 눈금**(항상 보이는 정보 — 언제 몰아칠지 계획할 수 있다), 판 위에 `.bossaura` 맥동(격노 뒤에는 붉게 남는다), 예고 배너도 기본 붉은색 대신 그 보스의 색. 색은 전부 `bosses.ts`의 `accent` 한 곳에서 `--boss` 변수로 내려오므로 **보스를 추가할 때 CSS는 안 건드린다**.

## ⑩ 런 밸런스 시뮬레이터 — `npm run sim:run` (2026-07-30)
`npm run sim`(단판 1:1 수치)에 이어, **런 전체**를 끝까지 돌려 난이도 곡선을 재는 도구(`scripts/simrun.ts`). 봇이 플레이어를 대신해 카드를 내고 보상·이벤트·상점까지 고른다. 1800런이 약 1초.

```bash
npm run sim:run                      # 기본 200런, 전 캐릭터, hard 봇
npm run sim:run 1800 -- --seed=12345 # 시드 고정(사다리·보상 재현) — 튜닝 전후 비교의 기본
npm run sim:run 1200 -- --skill=normal   # 봇 숙련도 = 플레이어 실력 모델
npm run sim:run 1200 -- --policy=random  # 보상·상점을 아무렇게나 고르는 하한선
npm run sim:run 1200 -- --path=greedy    # 분기 경로 정책 (template|random|greedy|safe) — ⑤-bis
npm run sim:run 600  -- --char=archer    # 직업 고정 (warrior|archer|mage)
npm run sim:run 900  -- --relics=coil,circuit,flywheel   # 특정 유물 조합을 들고 시작(조합 상한 측정)
```
캐릭터 밸런스는 **`--sweep`**(캐릭터별 클리어율 + 밴드 폭)으로 본다:
```bash
npm run sim:run 1500 -- --sweep --seed=12345
```
시작 덱은 전 캐릭터가 같은 **구성**(공용 6 + 직업 기본기 3)이라 차이는 **시그니처 유물 + 직업 기본기 + 보상으로 얻은 직업 카드를 얼마나 살리는가**에서 나온다. ⚠ 2026-08-04부터 기본기가 직업별이므로 **기본기 수치를 건드리면 이 스윕을 다시 돌려야 한다**(도입 시 밴드 3.6%p → 1.5%p, 클리어율 +3%p).
- **시드 RNG**: `Math.random`을 mulberry32로 갈아끼워(시뮬 프로세스 안에서만) 사다리 생성·보상 추첨·AI 확률 분기까지 재현 가능하게 만든다. 같은 시드로 다시 돌리면 **차이가 곧 수치 변경의 효과**다. 엔진 자체는 원래 랜덤이 없다.
- **리포트**: 클리어율 · 평균 도달 층 · **층별 관문(도달/통과율/사망 수/전투 진입 시 평균 체력비)** · 몬스터별(조우·플레이어 승률·평균 턴·평균 잃은 체력·처치한 런 수) · 캐릭터별 클리어율 · 보스 도달 시점 스냅샷(유물·덱·골드·체력) · 많이 집힌 유물.
- **정책 봇**: `greedy`(유물 우선 → 체력 낮으면 보상 포기 회복 → 카드 점수 최고 → 상점에서 유물·회복·좋은 카드)와 `random`. 카드 점수는 화력·범위·기력비에 **중복 감점**(같은 공격은 한 턴에 한 번만 쓰므로).
- **경로 정책(`--path`, 2026-08-04)**: 분기 지도가 생기며 "어느 길로 갔는가"가 클리어율을 직접 흔든다 — 무엇을 재는지 명시해야 한다. 기본은 `random`. **옛 기록과 비교할 땐 반드시 `--path=template`**(0번 고정 = 분기 이전과 같은 경로). ⚠ 그래도 시드까지 같게는 안 나온다 — 층마다 후보를 2개 뽑느라 **RNG 스트림이 밀리기** 때문이다. 경로는 같아도 몬스터·보상 추첨이 달라지므로 **분포로만** 비교할 것.
- **읽는 법(중요)**: 봇은 **줄을 바꿔 원거리 공격을 피하지 못한다**([GAME_DESIGN.md](GAME_DESIGN.md) ④ AI 한계). 그래서 절대 클리어율은 사람 기준보다 **비관적**이다 — 목표치가 아니라 *추세·상대 비교*로 읽어야 한다.

**튜닝 후 상태(2400~4000런 · seed 12345 · hard 봇 · greedy · 2026-07-31 시작 덱 개편 반영)**:

## ⑪ 캐릭터 밸런스 — 시그니처 유물의 런 수치 (2026-07-30 → 2026-07-31 재튜닝)

### 왜 런에는 별도 수치가 필요한가
캐릭터 패시브를 그대로 유물화하니 런 클리어율이 **27~57%**로 벌어졌다(캐릭터별 대량 시뮬). 원인은 두 가지 구조적 차이다:

1. **지속회복 > 피해감소** — 체력이 층 사이에 이어지므로, 감소는 출혈을 늦추기만 하고 회복은 되돌린다. 회복 수단이 없는 캐릭터는 층마다 누적 출혈로 죽는다. 민감도는 극단적이다: **회복 1포인트 ≈ 클리어율 +7%p, 흡혈 1포인트 ≈ +4.5%p**(EMBER는 흡혈 +4·재생 +3만으로 27%→67%가 됐다).
2. **제약은 기력이 아니라 슬롯 3칸** — 쿨0 공격도 턴당 1회뿐이고 기력은 턴마다 쌓이므로, 한 슬롯에 큰 카드를 넣는 쪽이 언제나 이긴다. 그래서 매 턴 기력을 크게 주는 패시브(NOVA +20)가 큰 카드를 매 턴 쏘게 해 압도한다.

그래서 `relics.ts`의 `SIGNATURE`에 **`runEffect`**(런에서의 실효 수치, 가감 모두)를 둔다. `ROSTER.passive`는 건드리지 않으므로 **PvP·봇전·1:1 시뮬은 불변**이다(검증: 1:1 승률 TITAN 56 · CIPHER 51 · AEGIS 51 · NOVA 48 · EMBER 47 · VOLT 46 — 변경 전과 동일).

## ⑫ 조합 유물 · 런 전용 카드 (2026-07-31)

### 설계 원칙 — "판을 부수는 조합"은 막지 않는다, 대신 도달이 어렵다
사용자 요구: *"유물을 조합해서 진짜 말도 안 되는 뽕맛을 느끼는 것도 하나의 플레이 루트다. 막지 않았으면 좋겠다. 대신 그것까지 매우 힘들어야 한다."*
그래서 **상한을 깎는 대신 확률로 조절**한다:
- 효과는 전부 **합산·중첩**된다. 주기가 다른 누적 기력 트리거는 합쳐지지 않고 **각자 따로** 터진다(`mergeRelics`가 배열을 이어 붙인다) — 조합이 약해지지 않게.
- 대신 **희귀도 가중 + 깊이 보정** 추첨(`rarityWeightAt`): 1층은 전설 ≈6%, 15층은 ≈17%. 얕은 층에서 전설을 긁을 수는 없고, **깊이 살아남은 대가**로 재료가 모인다.
- 유물 공급 자체가 제한적이다(런당 약 3개, 상점 유물 1칸).

**측정 결과**(`npm run sim:run 4000`): 획득 유물의 희귀도는 일반 36% · 희귀 36% · 영웅 24% · **전설 3.5%**. 클리어한 런 기준으로 **전설 1개 이상 18%**, 2개 이상 0.9%, **영웅+전설 3개 이상(= 조합 빌드 완성) 20%**. 즉 다섯 번 클리어에 한 번쯤 "판이 부서지는" 런이 나온다.

**조합의 상한 확인** — `--relics`로 원하는 조합을 들고 시작해 볼 수 있다:
```bash
npm run sim:run 900 -- --relics=coil,circuit,flywheel                    # 클리어율 78%
npm run sim:run 900 -- --relics=coil,circuit,flywheel,reservoir,deathwish,voidedge  # 88%, 전투 3.7턴
```
기본(유물 없이 시작)이 31%인데 조합이 완성되면 88%까지 간다 — 전투도 5.0턴 → 3.7턴으로 짧아진다. 의도한 "뽕맛"이 수치로 확인된다.

### 런 전용 카드 (`game/runcards.ts`, 50장)
보상·상점에만 나온다. **공용 카드나 캐릭터 고유 카드에 넣지 않으므로 덱 빌더(PvP·봇전)는 불변**이다.

- **각성**: 피의 각인(전투 내내 공격 +6, 중첩) · 울림의 파문(+4)
- **화력**: 파쇄 망치 42 · 꿰뚫는 화살 44(관통) · 십자 파열 32 · 지반 붕괴 34 · 광폭 난타 58(반동 16) · 소멸 포격 66(기력 58) · 생명 흡수(흡혈 16)
- **수비·회복**: 불락의 성채(방어 95) · 편향 장막(방어 55) · 치유의 성수(체력 +45) · 수혈(+26)
- **이동**: 순간 이동/역행 이동(3칸) · 비껴 딛기·낮춰 딛기(대각 2칸)

새 카드 능력은 엔진 필드로 들어간다: `stun`(기절) · `pull`(끌어당김) · `empower`(전투 내내 누적 공격력). 카드 UI에 능력 칩으로 표시된다(`기절1턴`·`끌기2`·`각성+6`).
